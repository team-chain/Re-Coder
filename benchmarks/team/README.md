# 팀 벤치마크 — 멀티 에이전트·테스트 리코더가 실제로 나아지는가

같은 요청을 구성만 바꿔 만들고, **사람이 쓴 판정 시험(oracle)** 으로 잰다.

| 구성 | 만드는 방식 |
|---|---|
| A 혼자 | 리코더 한 명(`mode=auto`). 요청이 크면 코어가 알아서 나눌 수 있다 — 결과의 `engine` 에 남는다 |
| B 팀 | 설계 → 개발 3명 동시 → 검토(`mode=team`), 테스트 끔 |
| C 팀+테스트 | B + 테스트 리코더: 만든 앱을 띄워 완성 기준을 시험하고, 실패하면 고친 뒤 다시 시험 |
| D 팀+테스트+역할별 모델 | C 와 같고 검토·테스트만 빠른 모델(균형 프리셋) — `--configs A,B,C,D` |

## 과제와 판정

- `tasks.json` — 과제 10개(메모·할 일·좋아요·인증·페이지·댓글·재고·짧은 주소·검색·입력 검사). 화면이 있는 과제 4개는 연결 오류도 잰다.
- 생성 쪽은 `prompt` 와 `criteria`(완성 기준)만 본다. `oracle` 은 생성이 끝난 뒤에만 쓴다 — 시험에 맞춰 만드는 것을 막는다.
- C·D 의 테스트 리코더는 같은 완성 기준으로 **스스로 만든** 시험을 쓴다. oracle 과는 다른 시험이다.
- `reference_app.py` — 요구대로 쓴 기준 구현과, 일부러 넣는 버그 목록(`BUGS`). 판정 시험이
  ① 기준 구현에서는 모두 통과하고 ② 버그마다 정확히 그 조건에서 실패하는지 확인한다:

```
python scripts/team_benchmark.py --check-oracle
```

## 재는 것

| 지표 | 뜻 |
|---|---|
| 판정 통과율 | oracle 이 있는 조건 중 통과한 비율. 앱이 뜨지 않으면 그 과제의 조건은 모두 실패 |
| 모두 통과한 과제 | oracle 조건을 전부 통과한 과제 수 |
| 실행 성공 | Docker 빌드가 되고 앱이 떠서 요청에 답했다 |
| 서버 오류 | 기본 흐름 요청(`runtime_check.scenario`)에서 5xx 가 난 경로 수 |
| 연결 오류 | 화면 코드가 부르는 `/api` 경로 중 서버에 없는 것(메서드까지, 정적 검사) |
| 보안 발견 | `code_security` 가 찾은 문제 수 |
| 시간 · AI 호출 · 비용 | 실행마다. 비용은 단가를 아는 호출만 더하고, 모르는 호출 수를 따로 적는다 |
| 통과 조건 1개당 비용 | 모든 실행의 비용을 알 때만 |

## 돌리기

```
python scripts/team_benchmark.py                                   # 계획·최대 호출 수만(무료)
python scripts/team_benchmark.py --live --budget 5                 # A,B,C × 과제 10개 = 30회
python scripts/team_benchmark.py --live --configs A,C --only T03-likes,T07-stock --repeat 3
python scripts/team_benchmark.py --report benchmarks/team/results  # 저장된 결과로 보고서만
```

- 필요: AI 연결(ReCoder 와 같은 설정), Docker(빌드·실행·판정).
- `--budget`(USD) 에 닿으면 다음 실행을 시작하지 않는다. 진행 중인 한 실행은 끝까지 간다.
- 결과: `results/runs.json`(실행마다) · `summary.json` · `report.md`. 같은 폴더로 다시 실행하면 이어서 한다.
- 과제 10개는 작은 표본이다. 차이가 몇 조건 수준이면 `--repeat` 를 늘려 다시 확인한다.

## 정직하게 읽기

- 이 벤치마크는 "요구한 API 계약을 지키는가"를 잰다. 화면의 보기 좋음·코드 구조 같은 것은 재지 않는다.
- B 가 A 보다 낫다는 보장은 없다 — 작은 과제는 한 번에 만드는 쪽이 더 싸고 정확할 수 있다. 결과를 그대로 적는다.
- 같은 모델·같은 날짜·같은 과제로 비교해야 의미가 있다. `report.md` 맨 위에 모델과 날짜가 적힌다.
