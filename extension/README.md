# ReCoder — AI DevOps Agent

> 채팅으로 요청하면 **설계 선택지**를 먼저 제시하고, 사람이 고른 결정에 따라 코드를 만들고,
> 그 결정을 ADR로 남기고, 배포·감시·롤백까지 한 흐름으로 이어주는 VS Code 확장.

**Preview** — 현재 MVP 단계입니다. 기능과 화면이 바뀔 수 있고, 피드백은
[GitHub Issues](https://github.com/team-chain/Re-Coder/issues)로 받습니다.

AI가 혼자 판단해 코드를 쏟아내지 않습니다. 갈림길이 있으면 **선택지 카드**를 띄우고,
사람이 승인한 뒤에만 진행합니다. 무엇을 왜 그렇게 정했는지는 `docs/adr/` 에 기록으로 남습니다.

## 무엇을 하나

| | |
|---|---|
| **설계 결정 먼저** | "할 일 앱 만들어줘" → 코드 대신 "데이터를 어디에 저장할까요?" 같은 선택지 카드. 고른 뒤에 코드가 나옵니다. |
| **결정 기록 (ADR)** | 승인된 선택은 `docs/adr/ADR-NNN-*.md` 로 자동 기록됩니다. 결정·근거·검토한 대안·영향 네 항목. |
| **에러 분석과 패치** | 터미널 출력을 읽어 원인을 찾고 수정안을 제시합니다. 적용 전 diff 확인, 적용 후 롤백 가능. |
| **인프라 파일 생성** | Dockerfile · docker-compose · GitHub Actions 초안을 프로젝트 구조에 맞춰 만듭니다. |
| **배포 전 검사** | 환경변수 누락, 포트, 시크릿 유출, 이미지 취약점을 배포 전에 걸러냅니다. 빌드가 확정적으로 실패할 설정(없는 파일을 가리키는 빌드 스크립트, 선언 안 된 패키지, 포트 불일치 등)은 빌드 전에 알려 주고, 안전한 항목은 버튼으로 고칩니다. |
| **배포** | 정적 사이트는 본인 AWS 계정 S3로, 컨테이너 앱은 ECS로. |
| **감시와 롤백** | 배포 후 health·에러율·메모리를 추적하다 이상하면 롤백을 제안합니다. |

모든 실행 단계에 **사람 승인**이 걸려 있습니다. 확장이 사용자 모르게 파일을 고치거나 배포하지 않습니다.

## 지원 환경

| OS | 상태 |
|---|---|
| Windows x64 | 지원 |
| Linux x64 | 지원 |
| macOS | 준비 중 |

확장에는 OS별 **Core 실행 파일과 Python 런타임이 함께 들어 있습니다.** Python·Node.js 설치나
빌드 없이 설치 후 바로 동작합니다. VS Code가 사용 중인 OS에 맞는 파일을 자동으로 받습니다.

## 시작하기

1. 확장을 설치하고 왼쪽 Activity Bar의 **R 아이콘**을 누릅니다. Core가 자동으로 실행됩니다.
2. AI 연결 방법을 하나 고릅니다 (아래 **AI 연결**).
3. **Develop** 화면의 **AI와 대화하기**에서 만들고 싶은 것을 요청합니다.

신뢰할 수 있는 워크스페이스에서만 동작합니다. Core 실행·파일 수정·배포를 하기 때문에,
VS Code의 제한 모드(Restricted Mode)에서는 비활성화됩니다.

## 화면

- **Develop**: 요청 → 설계 선택 → 생성된 코드의 diff 확인 → 적용. 에러 분석, 아키텍처, 설계 기록도 여기서 봅니다.
- **Deploy**: 프로젝트를 배포 대상에 끌어 놓고 설정과 승인 내용을 확인합니다. 워크스페이스에 폴더가 여러 개면 상단에서 배포할 프로젝트를 고릅니다(새로 추가한 폴더가 자동으로 선택됩니다). 보안 게이트는 검사 결과에 따라 초록(이상 없음)·빨강(이상 발견)·노랑(검사 미확인)으로 표시됩니다. 프로젝트를 누르면 파일·함수 구조를 탐색합니다. 배포 이력과 롤백도 이 화면에서 엽니다.
- **Security**: 검사를 시작하고 필요한 결과만 펼쳐 봅니다. AWS 연결과 Core·AI 연결 상태는 상단에서 확인합니다.

## AI 연결

**본인 AWS 계정 (기본)**
AWS 연결 화면에서 본인 프로필·브라우저 연결을 쓰거나 액세스 키를 직접 등록합니다.
필요한 최소 권한 정책은 확장이 만들어 보여줍니다. 해당 리전에서 Amazon Bedrock 모델을 쓸 수 있어야 합니다.

**Claude 또는 ChatGPT API 키 (AWS 없이)**
AWS 계정이 없으면 Anthropic(Claude) 또는 OpenAI(ChatGPT) API 키로 연결합니다.
Develop 화면의 **Claude API 키로 연결 / ChatGPT API 키로 연결** 버튼이나 명령 팔레트 →
`ReCoder: Connect AI with API Key (Claude / ChatGPT)` 에서 키를 붙여 넣으면 Core가 다시 시작되며 연결을 확인합니다.
기본 모델은 `claude-sonnet-5` / `gpt-5-mini` 이고 설정 `recoder.ai.anthropicModel` / `recoder.ai.openaiModel` 로 바꿀 수 있습니다.
배포(S3·ECS)는 여전히 본인 AWS 계정이 필요합니다.

**게이트웨이 (수업·팀에서 등록 코드를 받은 경우)**
운영자에게 받은 게이트웨이 주소를 설정 `recoder.gateway.url` 에 넣고,
명령 팔레트 → `ReCoder: Connect to Gateway (Enroll)` → 등록 코드를 입력합니다.

## 데이터와 개인정보

ReCoder는 사용 통계나 텔레메트리를 수집하지 않습니다. 다만 기능 특성상 다음 데이터가 기기 밖으로 나갑니다.

- **AI 요청** — 요청 문장과, 답을 만들기 위해 필요한 코드 일부·터미널 출력·프로젝트 구조 요약이
  **본인 AWS 계정의 Amazon Bedrock**, **설정한 게이트웨이**, 또는 API 키로 연결한 경우 **Anthropic·OpenAI API**로 전송됩니다.
  환경변수 `GEMINI_API_KEY` 를 직접 설정한 경우에만 Bedrock 실패 시 Google Gemini가 대체로 쓰입니다.
- **배포** — 배포를 승인하면 빌드 결과물과 이미지가 **본인 AWS 계정**(S3·ECR·ECS)으로 올라갑니다.
- **GitHub** — 연결하고 푸시를 승인한 경우에만 지정한 저장소로 커밋이 올라갑니다.
- **Discord** — 연동을 켠 경우에만 설정한 채널로 배포 알림이 갑니다.

자격증명과 AI API 키는 기기 안에만 저장됩니다. VS Code 보안 저장소(OS 키체인)에 두며,
`recoder` 프로필 방식을 고른 경우 `~/.recoder/aws_credentials.json` 에 사용자 전용 권한으로 저장됩니다.
Core는 `127.0.0.1` 에서만 열리고, 확장이 발급한 세션 토큰이 있어야 호출할 수 있습니다.

## 요구 사항

- VS Code 1.85 이상
- 컨테이너 빌드·배포: Docker Desktop (정적 사이트 배포는 불필요)
- AWS 배포: 본인 AWS 계정

## 알아두실 것

- AWS 배포는 본인 계정에 실제 리소스를 만듭니다. 요금이 발생할 수 있으니 배포 전 예산 알림을 걸어두세요.
- AI가 만든 코드와 인프라 파일은 **초안**입니다. 적용 전에 확인하세요. 확장이 승인 단계를 두는 이유가 그것입니다.
- 문제가 생기면 Core 로그 `~/.recoder/core.log` 를 이슈에 함께 첨부해 주세요.
