# Changelog

## 1.1.29 — 2026-10-04 (Preview)

**보안 게이트**
- ReCoder 가 만든 Dockerfile 이 보안 게이트를 빨간색으로 만들던 문제를 고쳤습니다. 템플릿은 Dockerfile 검사(Hadolint)를 통과하고, 버전 고정 권고처럼 보안·동작 문제가 아닌 항목은 "중간"으로 셉니다.
- 하위 폴더 의존성을 설치하는 자동 수정이 `RUN cd` 대신 `WORKDIR` 를 씁니다(같은 동작).
- 보안 검사 수정안이 `RUN cd …` 를 WORKDIR 로, 셸 형식 CMD·ENTRYPOINT·HEALTHCHECK 를 같은 동작의 JSON 형식으로 고칩니다.
- Dockerfile 검사 결과를 AI 영어 요약 대신 "무엇이 몇 번째 줄에" 로 보여 줍니다.

**코드 생성**
- 문을 닫은 이미지 서비스(via.placeholder.com·placeimg.com) 주소를 쓰지 않습니다. 이미 만든 프로젝트는 배포 점검에서 자동 수정(placehold.co)을 누를 수 있습니다. DB 에 이미 들어간 초기 데이터는 다시 넣어야 합니다.

**CI**
- 골든패스 스모크가 1.1.26 부터 실패하던 문제: 가짜(moto) S3 로 도는 기본 모드에서는 실제 S3 주소의 화면 확인을 하지 않습니다(--live 는 그대로 확인).
- GitHub Actions 를 Node 24 로 도는 버전으로 올렸습니다.

## 1.1.28 — 2026-10-02 (Preview)

develop(1.1.27) 전체 점검에서 재현한 문제를 고쳤습니다. 맞게 쓴 코드는 건드리지 않도록 자동 수정을 좁혔고, 비밀 값이 AI 로 나가지 않게 했습니다.

**로컬 Docker 배포**
- Dockerfile 이 없는 Python·정적 사이트는 계획 단계부터 템플릿이 실제로 여는 포트를 씁니다(예: Flask 5000 인데 8000 으로 확인해 "응답 없음"이 되던 문제).
- 회사 PC 처럼 시스템 프록시가 있어도 로컬 컨테이너 헬스 확인은 프록시를 거치지 않습니다.
- 폴더 이름이 같은 다른 프로젝트(C:\work\shop 과 D:\other\shop)가 서로의 컨테이너·DB 를 덮어쓰지 않습니다(예전 컨테이너는 그대로 이어 씁니다).
- 시작이 느린 앱(빌드·마이그레이션 중)은 화면 확인 때문에 실패·되돌림 처리하지 않고 "확인 중"으로 둡니다. 웹 컴포넌트(shadow DOM) 화면은 빈 화면으로 단정하지 않습니다.
- 프로젝트에 init.sql·schema.sql 이 있으면 처음 만든 PostgreSQL 에 한 번 실행해 테이블과 초기 데이터를 만듭니다(재배포 때는 손대지 않습니다).
- Dockerfile 을 두 번 덮어써도 손으로 고친 원본 백업이 남습니다. 메모장 ANSI 파일의 비교 화면이 깨지지 않습니다.

**자동 수정이 맞는 코드를 망가뜨리지 않도록**
- uploads·data 같은 폴더를 화면 빌드 폴더로 바꾸지 않습니다(빌드가 그 폴더를 비울 수 있었습니다).
- __dirname 정의를 함수 안에 끼워 넣거나, 같은 이름의 CommonJS 파일 두 개를 같은 변수로 가져오던 변환을 고쳤습니다.
- import 와 module.exports 를 섞은 파일, 최상위 await·import 속성·여러 이름 export 처럼 확실히 바꿀 수 없는 파일은 반쪽만 고치지 않고 안내합니다.
- "type": "module" 을 뺄 때 Vite 화면 소스의 이름을 바꾸지 않습니다. createRequire 를 쓰는 ESM 서버를 CommonJS 로 오판하지 않습니다.
- UTF-8 이 아닌 파일이 섞여 있으면 아무것도 바꾸지 않고 이유를 알립니다(한글 주석이 깨지지 않게).
- pg 숫자 파서를 pg 를 쓰는 모든 파일에 넣습니다. 환경변수로 정한 axios baseURL 의 '/api/…' 는 그대로 둡니다.
- `node -r dotenv/config server.js`, 템플릿 문자열 속 import, Tailwind 용 package.json 이 있는 Django 를 잘못 판정하지 않습니다.

**보안**
- 코드 생성 때 열려 있던 .env·키 파일 본문은 AI 로 보내지 않고, 코드 속 키·접속 비밀번호는 가려서 보낸 뒤 결과에서 원래 값으로 되돌립니다.
- 오류 분석 마스킹이 SECRET_KEY=…, DB_PASS="a b", postgres://user:비밀번호@…, github_pat_… 를 가립니다.
- S3 공개 버킷에 소스맵(.map)을 올리지 않습니다(원본 소스가 공개되던 문제).
- 디스코드 봇: API 주소로 메타데이터·링크 로컬 주소를 받지 않고, 브리지 토큰을 상수 시간으로 비교합니다.
- 보안 패치가 나온 의존성으로 올렸습니다(starlette, anyio, urllib3, cryptography, httplib2, pyasn1, pydantic-settings, multer).

**중간 단계 글자 줄이기**
- 코드 생성 결과는 파일 목록과 개수만 먼저 보이고, 파일 이름을 누르면 내용이 펼쳐집니다(파일 수십 개의 내용이 화면을 덮던 문제).
- Docker 배포의 점검·승인·결과 화면은 문제마다 첫 문장 한 줄만 보이고 원문·해결 설명은 접어 둡니다. 같은 점검 문장이 초안·승인 창에 거듭 나오지 않게 했습니다.
- 생성 중·설계 결정 창의 긴 안내 문장을 줄였습니다.
- 모노레포(npm workspaces) 로컬 배포: 루트 start 가 `npm start --workspace=backend`·`npm --prefix server start`·`cd api && npm start` 처럼 다른 패키지로 넘기면 그 패키지의 서버 파일을 찾아 Dockerfile CMD·포트를 정합니다(예전엔 없는 index.js·3000). 이미 저장된 Dockerfile 은 배포 직전에 CMD·포트·서버 폴더 의존성(`--workspaces=false`)을 자동으로 고치고, 바뀐 포트에 맞춰 연결합니다.
- 이미지 취약점 검사 결과가 AI 요약 대신 "검사한 이미지·빌드 시각 — 패키지 버전 → 고친 버전(건수 · 어디서 왔는지)" 로 나옵니다. 배포 계획 단계의 HIGH 결과에도 "이전에 빌드된 이미지 기준"을 붙였습니다.
- "확장이 요청을 받지 못했습니다" 대책: 확장이 다시 시작돼도(VSIX 설치 뒤 확장 다시 시작, 빈 창에 폴더 추가 등) 열려 있던 ReCoder 탭을 새 확장에 다시 연결합니다. 그래도 끊기면 창 맨 위에 바로 알리고, 보낸 요청은 30초가 아니라 15초 안에 실패를 알리며 보낸 내용을 입력창에 되돌려 둡니다.
- 코드 생성 요청 화면: 제목·설명 문장을 빼고 "무엇을 만들까요?" 와 입력창 하나만 둡니다. 위치·참고 파일·보내기를 입력창 안에 모았고, 보낸 요청은 말풍선(위치·참고 파일 표시)으로 남습니다. 이어서 수정할 때는 입력창이 화면 아래에 붙어 있습니다.

**배포 다시 점검 (2026-10-03)**
- 작업 폴더 밖의 프로젝트를 골라도 VS Code 작업 영역을 바꾸지 않습니다. 그래서 확장이 다시 시작되지 않고, 창을 다시 불러와도 보던 화면과 입력 중인 요청이 남습니다.
- 로컬 Docker: 루트 package.json 에 설치할 패키지가 없는 프로젝트(client/ + server/)도 빌드됩니다. Next.js 이미지에서 npm 을 최신으로 올리던 단계(npm 12 부터 실패)를 없애고 node 로 바로 실행합니다. 이미 저장된 Dockerfile 은 배포 직전에 고칩니다. 기본 Node 버전은 22 입니다(20 지원 종료).
- 로컬 Docker: TypeScript(dist) 진입점과 `Number(process.env.PORT) || 8080` 같은 포트를 읽습니다. 시작하자마자 죽는 앱은 "느린 시작"이 아니라 실패로 판정해 이전 버전을 되살리고, 실제 오류(파일:줄)와 DB 를 localhost 로 찾는 경우를 알려 줍니다.
- 로컬 Docker: 프로젝트의 .env 값을 컨테이너 환경변수로 넘깁니다(PORT 처럼 배포가 정하는 값은 제외하고, 값은 기록하지 않습니다).
- ECS: recoder.yml 이 없는 서버 앱이 "PORT 가 .env 에 없음·포트 3000 불일치·PC 포트 3000 사용 중" 같은, 사용자가 정한 적 없는 조건으로 막히던 문제를 고쳤습니다. 헬스 경로가 없거나 .env 가 커밋 대상인 것은 경고로 알립니다(.env 가 이미지에 들어가면 계속 막습니다). ECS 태스크에 PORT 를 넘깁니다.
- 배포 캔버스의 S3·ECS 는 AWS 공식 아키텍처 아이콘, Docker·GitHub·Discord 는 각 로고를 씁니다.
- 보안 검사가 찾기만 하고 끝나지 않습니다. 결과로 바로 적용할 수 있는 수정안을 만들고(베이스 이미지 OS 패치·새로 받기, 이미지 속 npm 제거, 취약한 npm·pip 패키지 올리기(하위 의존성은 overrides, lock 갱신), Dockerfile 규칙, 코드에 적힌 키를 .env 로 옮기기), 고른 것만 적용한 뒤 바뀐 부분을 다시 검사합니다. 이미지 취약점은 이미지를 다시 빌드한 뒤 검사합니다. 메이저 버전이 바뀌는 수정은 기본으로 고르지 않고, 원본은 .recoder/backups 에 남깁니다(키 값은 백업하지 않습니다).
- 커밋에서도 이미지에서도 빠지는 .env 의 키는 시크릿 유출로 세지 않습니다(키를 보관하는 올바른 위치입니다).

**확장**
- 코드를 만든 뒤 현재 프로젝트를 바꿔도 적용·비교는 만든 프로젝트에만 합니다. 프로젝트 밖을 가리키는 폴더 링크 아래에는 새 파일도 만들지 않습니다.
- S3 배포 승인 뒤 현재 프로젝트가 바뀌면 배포를 멈춥니다. 권한 부족(403)·계정의 퍼블릭 액세스 차단을 각각 맞는 해결책으로 안내하고, 새 버킷이 열릴 때까지 화면 확인을 기다립니다. PDF·CSV 등도 올바른 형식으로 올립니다.
- 터미널 오류 자동 분석이 명령 출력을 실제로 받습니다(예전엔 항상 빈 출력). "Stop Core" 뒤 Core 가 몇 초 만에 다시 켜지지 않습니다.
- 탐색기 "여기에 코드 생성"이 ReCoder 창의 코드 화면을 열고 그 폴더를 대상으로 둡니다. Discord 알림 설정이 현재 프로젝트를 기준으로 합니다. AWS 키 검증 실패 이유를 보여 줍니다.

## 1.1.27 — 2026-10-01 (Preview)

실기기에서 "개발 요청 응답이 없습니다"와 로컬 Docker 배포 실패(옛 이미지 실행)를 원인부터 고치고, develop(Discord 로그인 연결)을 흡수했습니다.

**개발 요청이 멈추지 않도록**
- 작업 폴더를 바꿔 확장이 다시 시작된 뒤 Core 준비가 끝나지 않으면 이후 모든 요청이 영원히 기다렸습니다. 기다림마다 상한을 두고, 멈춘 단계를 core.log 에 남기며, 화면은 "요청이 확장에 닿지 않음"과 "Core 가 오래 걸림"을 구분해 해야 할 일을 알려 줍니다.
- 큰 요청(쇼핑몰)은 단계별로 기다리는 시간을 늘렸고(생성 최대 15분), Core 는 9분 예산 안에서 AI 교정을 멈춥니다.
- 코드 생성·적용·지도·배포가 모두 같은 "현재 프로젝트"를 봅니다(여러 폴더를 연 창에서 다른 폴더에 만들고 다른 폴더를 배포하던 문제).

**로컬 Docker 배포**
- Dockerfile 이 없는 프로젝트를 배포할 때 로컬에 남은 예전 이미지를 띄우지 않고, 검증된 템플릿으로 지금 코드를 빌드합니다.
- 프로젝트가 하위 폴더(예: docs/)에 있으면 승인 전에 그 폴더를 알려 줍니다.
- 빌드·실행을 막는 문제는 배포 직전에 자동으로 고치고(원본 백업) 무엇을 고쳤는지 보여 줍니다. 배포 뒤 화면이 실제로 보이는지도 표시합니다.
- 새 점검·자동 수정: 화면 빌드 폴더(vite outDir)와 서버가 제공하는 폴더 불일치, 선언만 하고 내보내지 않은 이름·기본 내보내기 누락·객체 안의 함수를 이름으로 가져오기, axios baseURL '/api' 에 '/api/…' 중복. 코드 생성 단계에서도 먼저 고칩니다.
- DB 볼륨은 남았는데 보관한 비밀번호가 바뀐 경우 PostgreSQL 비밀번호를 맞춰 앱이 접속하도록 합니다. PostgreSQL 준비 확인은 초기화용 임시 서버가 아닌 실제 서버를 기다립니다.
- 실패한 수동 롤백은 교체하려던 컨테이너를 다시 띄웁니다. PC 포트 충돌은 게시 목록에서 직접 읽습니다.

**Windows·가장자리**
- UTF-8 이 아닌(메모장 ANSI·PowerShell UTF-16) 기존 Dockerfile 은 충돌로 보고 원래 바이트로 백업합니다. BOM 이 붙은 package.json·requirements 를 올바르게 읽습니다. CRLF 파일에도 pg 숫자 파서를 넣습니다.
- 커버리지 리포트(htmlcov)·문서 사이트의 index.html 로 API 서버를 화면 앱으로 오판하지 않습니다.
- S3 업로드 중 네트워크 오류는 할 일을 알려 주는 메시지로 끝납니다.

**화면이 실패를 성공으로 보이지 않도록**
- Workbench: Core 가 실패(status: error·exists)를 돌려주면 실패로 표시하고, 기존 Dockerfile 이 있으면 덮어쓸지 묻습니다. 미리보기에서 고친 내용을 저장합니다. ECS 사전 점검 실패·배포 오류가 상태 줄에 표시됩니다.
- Docker 화면은 다른 기능(AWS 연결 등)의 오류로 진행 중인 작업을 실패로 바꾸지 않습니다. diff 열기 실패가 진행 중인 코드 생성을 실패로 만들지 않습니다.
- ECS 권한 확인·권한표가 실제로 푸시하는 ECR 저장소를 기준으로 합니다.

**develop 흡수 (윤세빈)**
- Discord 로그인(OAuth) 연결과 배포 알림을 합쳤습니다. 로그인이 기본이고, 로그인 서버가 없으면 내 봇 토큰·웹후크로 바로 연결할 수 있습니다. 로컬 Docker 결과 알림은 develop 의 중복 없는 방식 하나로 보냅니다.

## 1.1.26 — 2026-09-30 (Preview)

실기기(TEMP 쇼핑몰)에서 로컬 Docker·S3 배포가 "주소만 열리고 화면은 표시되지 않던" 문제를 원인부터 고치고, 배포가 끝나면 화면이 실제로 그려지는지 직접 확인합니다.

**배포 후 화면 확인(새 단계)**
- 로컬 Docker·S3 배포 직후 PC 의 Edge·Chrome 을 화면 없이 띄워 첫 화면을 열고, 스크립트 실행 뒤 보이는 내용이 있는지 확인합니다. HTML·JS·CSS 응답(없는 스크립트 대신 index.html 이 오는 경우, 빌드하지 않은 개발용 index.html, 잘못된 형식)도 함께 봅니다.
- 화면이 비면 "배포 완료"로 표시하지 않습니다 — 원인(콘솔 오류 포함)과 해결 방법을 보여 주고, 로컬 Docker 는 이전 배포가 있으면 되돌립니다. 화면이 없는 API 서버는 판정하지 않습니다. 브라우저가 없으면 HTTP 확인까지만 하고 그렇게 알립니다.

**배포 준비 점검·코드 생성 자동 교정(새 항목)**
- 서버 파일끼리 ESM(import)·CommonJS(require)가 섞여 컨테이너가 시작 직후 죽는 경우(TEMP 의 실제 원인: "does not provide an export named 'default'") → 서버 진입 파일 형식으로 통일합니다. CommonJS 파일은 .cjs 로, require 로 불리는 ESM 파일은 require 형식으로, 확장자 없는 ESM import·선언 없는 `__dirname`·import 와 require 가 섞인 파일·Node 가 찾지 못하는 이름 가져오기까지 고칩니다. 실제 node 로 실행해 확인한 9가지 형태를 테스트로 고정했습니다.
- 서버가 client/dist 를 화면으로 제공하는데 루트 `build` 가 없어(`build:client` 만 있음) Docker 빌드가 화면을 만들지 않는 경우 → `build` 를 연결합니다(TEMP 의 두 번째 원인).
- 코드 생성 직후 위 두 가지를 결정적으로 먼저 고치고, 남은 빌드·실행 오류는 AI 교정을 최대 3번까지 반복합니다(오류가 줄지 않으면 멈춤).

**S3**
- `build` 가 없고 `build:web`·`build:client` 같은 스크립트만 화면을 빌드하는 프로젝트도 빌드해서 올립니다.
- 빌드 전에 화면을 멈추게 하는 문제(process.env·.js 안의 JSX·없는 import 등)를 배포 확인 카드에 알립니다. API 서버가 필요한 화면은 S3 에서 데이터가 비어 보인다는 안내를 분명히 했습니다.
