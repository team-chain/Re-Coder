# Changelog

## 1.1.10 — 2026-09-25

- 첫 커밋 전에 추가했다가 삭제한 파일 때문에 커밋·푸시가 막히던 문제를 수정했습니다. 선택하지 않은 스테이징 파일은 보존합니다.
- 이미 연결된 GitHub 저장소를 변경하거나 새 비공개 저장소를 만들 수 있습니다. 연결 변경과 파일 푸시는 별도로 진행합니다.
- 로컬 Docker 실행에 SSE 단계 표시를 연결하고, S3 캔버스에 단계·업로드 파일 수·진행률을 표시합니다. 기존 승인·보안 검사·롤백을 유지하고, 연결 종료를 배포 성공으로 처리하지 않습니다.

## 1.1.9 — 2026-09-25

- 배포 아키텍처에서 프로젝트·파일·함수 구조로 들어갈 때 캔버스가 갑자기 확대되던 문제를 수정했습니다. 같은 기준 배율을 유지하고, 큰 소스 구조는 스크롤로 탐색합니다. 확대·축소 버튼과 기존 3D·드래그 배포는 유지합니다.

## 1.1.8 — 2026-09-25

- HTML/CSS/JS만 있는 프로젝트도 AI나 npm 없이 Dockerfile을 생성하고 nginx로 배포합니다. 새 자산은 재빌드에 자동 포함하며 내부 기록·숨김 파일은 제공하지 않습니다.
- GitHub 패널에서 변경 파일 선택 → 첫 커밋/추가 커밋 → 승인 후 푸시를 진행합니다. 다른 스테이징 파일은 보존하고, 검토 이후 파일이 바뀌면 재확인합니다.
- Discord 웹후크 간편 연결과 명시적인 테스트 전송을 추가했습니다. 주소는 프로젝트별 VS Code SecretStorage에 보관합니다. 기존 봇 서버 방식은 별도 옵션으로 유지합니다.
- ADR의 실제 승인 상태를 읽어 설계 확정을 표시합니다. 검토자 항목이 없다는 이유만으로 미검토로 표시하지 않습니다.
- S3 사전 검사에서 컨테이너 이미지 검사를 요구하지 않으며, 환경 파일이 없는 정적 사이트에 불필요한 Git 설정을 요구하지 않습니다. ADR과 ReCoder 내부 기록은 정적 업로드에서 제외합니다.

## 1.1.7 — 2026-09-25

- Bedrock의 일시 장애를 재시도하고, 설정되지 않은 Gemini 오류가 실제 실패 원인을 가리던 문제를 수정했습니다. 인증 오류는 불필요하게 반복하지 않으며, 설계 생성 오류와 대기 시간을 정리했습니다.
- React 플러그인이 있는 일반적인 Vite 설정을 서버 프로젝트로 잘못 분류하던 문제를 수정했습니다. 정적 빌드 결과를 확인한 뒤 nginx로 실행하므로 존재하지 않는 index.js를 실행하지 않습니다.
- 컨테이너 시작 명령만 성공하고 앱이 종료·재시작하는 경우 배포를 실패로 판정합니다. 이전에 검증된 컨테이너가 있으면 복구하고, 아직 HTTP 응답이 없는 실행은 검증 대기로 표시합니다.
- hadolint JSON 실행·검증과 Trivy 캐시를 보완했습니다. 스캔 결과가 없을 때 불필요한 AI 요약을 생략하고, 요약이 지연돼도 실제 검사 결과를 표시합니다.
- Docker Desktop의 부가 정보 조회가 멈추면 실행 중인 엔진도 꺼졌다고 오판하던 준비 검사를 서버 버전 조회로 교체했습니다.
- 정적 프런트엔드 런타임을 만들 때 Alpine 패키지 보안 업데이트를 적용합니다. 기존에 생성한 정적 Dockerfile의 포트·헬스 검사 인식은 유지합니다.

## 1.1.6 — 2026-09-24

- 코드 생성의 출력 토큰 한도와 temperature가 중간 라우터에서 사라지던 문제를 수정했습니다. Bedrock 구조화 응답·일반 응답과 Gateway·Gemini 경로에 요청값을 전달합니다.
- 코드 생성 시 JSON 스키마로 파일 작업을 요청하고, 출력 잘림·깨진 JSON·빈 변경 목록·파일 내용 누락을 검증합니다. 실패 시 같은 요청과 승인된 설계로 한 번 교정하며, 불완전한 파일 묶음을 성공으로 반환하지 않습니다.
- 파싱 실패를 감싼 임시 객체가 정상 응답으로 전달되던 문제를 수정했습니다. 복구 실패 시 파일이 변경되지 않았다는 설명과 원인을 표시합니다.
- 생성 및 한 번의 교정에 맞춰 대기 시간을 조정했습니다. TypeScript JSX 설정과 불필요한 React import에 대한 생성 지시도 보완했습니다.
- 실제 Bedrock으로 React·TypeScript·Tailwind 게시판 생성, 출력 잘림 복구, 후속 코드 수정과 빌드를 검증했습니다.

## 1.1.5 — 2026-09-24

- 오른쪽 AI 대화 패널을 제거하고 Develop → 코드 생성·수정 안에 대화 입력과 변경 결과를 함께 표시합니다.
- 요청을 보내면 바로 설계 선택을 시작합니다. 별도의 채팅 생성 승인 단계를 거치지 않으며, 설계 확인과 파일 적용은 사용자가 직접 선택합니다.
- 폴더·참고 파일, 이어서 수정, 설계 선택·ADR·diff·파일별 적용을 유지합니다. 중복 전송과 한글 조합 중 단축키 전송을 방지하고 오류·취소·시간 초과 후 다시 요청할 수 있습니다.
- 중앙 입력창에서도 AI 연결 확인과 재진단을 사용할 수 있습니다. 1.1.4의 시작 시 연결 복구와 Three.js 배포 캔버스를 유지합니다.

## 1.1.4 — 2026-09-24

- 개발 요청과 질문을 하나의 AI 대화로 통합했습니다. 중앙은 설계 결정과 변경 검토·적용 영역이며 폴더·참고 파일 선택도 대화창에서 이어집니다.
- 탭을 이동해도 대화와 변경 결과가 유지되고, 진행 중인 설계 요청이 중복 승인으로 덮어써지지 않도록 했습니다.
- 시작 시 Core 연결과 자격증명 복원을 공유하고 진단 중복 실행을 방지합니다. AI 확인이 느려도 Core 상태 조회와 대화 요청은 응답할 수 있습니다.
- Core 상태와 AI 진단 상태를 구분하고 진단 실패 시 다시 확인할 수 있습니다. 일반 작업 오류를 Core 연결 실패로 표시하지 않습니다.
- Gateway 사용자의 AI 진단이 로컬 AWS 자격증명을 요구하던 문제를 수정했습니다. 기존 설계 선택·ADR·diff·승인 적용과 Three.js 배포 캔버스를 유지했습니다.
- 설계 요청의 프로젝트 목록 수집에서 제외 폴더를 먼저 걸러내고 파일 상한에 도달하면 탐색을 종료합니다. 대형 의존성 폴더 전체를 정렬하던 지연을 제거했습니다.

- 기존 개발·배포·GitHub·Discord 기능과 1.1.2의 배포 수정을 포함합니다.

## 1.1.2 — 2026-09-24

- 로컬 배포에서 사용자가 지정한 포트, 환경변수, 프로젝트 정보와 감시 설정을 실제 실행·이력·롤백까지 유지합니다.
- 재빌드한 이미지를 다시 검사하고 검사한 이미지 ID로 실행합니다. 검사 차단 뒤 재시도로 검사를 건너뛰지 않으며, 새 검사 오류는 승인 상태에 따라 재확인을 요구합니다.
- Docker 멀티스테이지의 최종 런타임 포트를 감지해 ECS 설정에 반영합니다. 생성한 React 정적 이미지의 포트 불일치는 AWS 변경 전에 차단하며 ECS 헬스 체크는 nginx 런타임의 wget을 사용합니다.
- 로컬 Next.js·서버 앱의 실제 헬스 경로를 감지하고, 한국어 Windows 빌드 로그와 긴 빌드·검사 응답 대기를 수정했습니다.
- React 정적 Dockerfile 저장 승인에 기본 .dockerignore 생성을 안내하고 함께 생성합니다. 기존 제외 규칙은 유지합니다.
- 비어 있거나 손상된 Trivy·Gitleaks 보고서와 Hadolint 실행 실패를 검사 통과로 처리하지 않습니다.
- S3 업로드 전에 빌드하지 않은 CRA/Vite 진입 파일을 찾아 빌드 산출물 선택을 안내합니다.
- GitHub·Discord 연결과 이전 1.1.1의 개선을 모두 포함합니다.

## 1.1.1 — 2026-09-24

- GitHub 로그인 상태와 저장소 연결을 분리했습니다. 기존 저장소 선택, 비공개 저장소 생성, 첫 커밋 안내와 푸시 승인을 캔버스에서 진행합니다.
- 첫 커밋 전 브랜치·원격 정보가 사라지는 문제, AWS 상태에 GitHub 푸시가 묶이는 문제, 미인증 푸시 오류와 SSH 원격 주소 처리를 수정했습니다.

- Discord를 연결 전에도 Three.js 캔버스에 표시합니다. 봇 서버 연결 실패 안내, 연결 설정 진입과 재연결을 추가했습니다.
- 변경 파일이 0개인 에러 분석 결과에는 패치 적용 버튼을 표시하지 않습니다.
- CRA 및 기본 Vite 클라이언트 앱은 정적 빌드 결과를 Nginx에서 제공하는 Dockerfile을 생성합니다. Express용 `node index.js` 실행을 잘못 적용하지 않습니다.

## 1.0.0 — 2026-09-19 (마켓플레이스 첫 게시 후보)

### 추가
- AI-DLC 설계 결정 카드: 코드 생성 전에 구조에 영향 주는 선택을 사람이 고른다.
- 워크스페이스 허브(Develop · Deploy · Security)와 채팅 승인 카드 흐름.
- S3 정적 사이트 배포 — 진행 상황을 SSE 로 실시간 표시.
- ECS 배포·감시·롤백 제안→승인 흐름.
- AWS 원클릭 IAM 셋업 — 최소권한 사용자·키를 CloudFormation 으로 생성.
- 구조 지도(CodeMap): 프로젝트 import 그래프와 파일 내부 호출 그래프, 고립·과부하 진단.

### 안전장치
- 보안 스캔 미실행은 "통과"가 아니라 "확인 못 함"으로 표시하고 승인 강도를 올림.
- 빌드 전 이미지를 Trivy 에 넘기지 않음 — 실행 시점(빌드 후) 1회 스캔 보장, CRITICAL 차단.
- 배포 허용 조건은 OPA 정책(.rego) 한 곳에 선언 — 판정 불능이면 차단(fail-closed).
- 에이전트 로드 실패가 200 OK 로 위장되던 응답 제거(503 + 사유).
- LLM 라우터 단일화 — 서킷브레이커·게이트웨이·비용 집계가 전 경로에 적용.

### 수정
- 로컬 배포 컨테이너 이름에 이미지 태그가 들어가 400 나던 문제.
- 순수 파이썬 프로젝트가 python-fastapi 로 오분류되어 컨테이너가 즉사하던 문제.
- 워크벤치 사이드바 버튼 무반응(핸들러 공통 호스트로 통합).
- 코어에 라우트가 없는 EC2 배포 UI 제거(404 방지).
