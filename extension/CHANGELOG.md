# Changelog

## 3.0.2 — 2026-10-24 (Preview)

**화면을 새로 — 글보다 그림으로**
- 로고 색(청록 → 스틸 블루)으로 모든 화면 톤을 맞췄습니다. 글꼴은 Pretendard(확장에 내장), 밝은 테마 · 고대비도 맞춥니다.
- 홈: 지금 서비스 중인 앱 미리보기, 요청 · 오류 그래프, 보안 링, 승인 대기, 배포 경로(GitHub · Docker · ECS · S3 실제 로고), 커밋 전 바뀐 코드 — 모두 실제 데이터.
- 위쪽 탭(홈 · Develop · Deploy · Security · Operate)을 누르면 바로 그 화면, 그 아래 한 줄에 그 영역의 모든 기능.
- 화면 아래 요청창 — 적은 내용이 코드 생성 입력칸으로 넘어갑니다.
- 캐릭터와 ✓ · ✕ 같은 글자 기호를 없애고 로고 · 선 표시만 씁니다.

**AWS · GitHub · 서비스를 바꾸는 요청은 모두 확인 후에만**
- ECS 배포, S3 공개 배포, IAM 역할 설정, GitHub push · 저장소 · Secret, 서비스 중지, 로컬 롤백, GitOps prune · force, 감시 알림 설정은 확인 단계를 거쳐 approved 가 있어야 코어가 실행합니다.
- GitHub 브랜치 이름 검사, force push 는 --force-with-lease 로만.

**보안 · 정확성**
- 세션 토큰은 Core 를 켤 때마다 새로. GitHub Actions 는 Preflight 하나만 부를 수 있는 CI 토큰(RECODER_CI_TOKEN), Discord 봇은 연동 토큰(~/.recoder/integration_token)을 씁니다.
- SSH 대상 검사(옵션 주입 차단), 심볼릭 링크로 프로젝트 밖에 쓰는 것 차단, ArgoCD TLS 검증, 5xx 응답에 원문 오류를 싣지 않음.
- 롤백 대상은 "마지막으로 성공한 배포"만. GitOps 되돌리기 PR 이 실제로 되돌리게, 로컬 롤백이 .env 를 유지하고 헬스 실패 시 원래 컨테이너 복구.
- 공유 ECR 저장소 · 남의 보안 그룹을 덮어쓰지 않음, 배포 취소 시 남은 과금 리소스 경고, 감시 승인 링크가 실패해도 다시 쓸 수 있게.

## 2.0.48 — 2026-10-24 (Preview)

**모니터 — 한 화면에서 밤사이 일 · 승인 대기 · 24시간 감시자**
- 위쪽 탭에 **Monitor** 가 생겼습니다. 승인할 일이 있으면 숫자 배지가 붙습니다.
- 서비스 상태(요청 · 오류율 · 실행 중 태스크 · 감시자), 24시간 그래프, 「일어난 일」(감시자 기록 + VS Code 가 켜져 있을 때 감지한 알림, 마지막으로 본 뒤 생긴 것에 「새로」), 「승인 대기」(이전 버전 롤백 · IP 차단 등), 감시 설정을 한 화면에.
- VS Code 를 열면(그리고 30분마다) "밤사이 n건 · 승인 대기 m건" 을 알려 줍니다 — [모니터 열기].
- 실행은 모두 승인 뒤에만, 그리고 누른 뒤 한 번 더 확인합니다.

**24시간 감시자 — PC 가 꺼져 있어도 내 AWS 안에서**
- 모니터에서 「설치 내용 확인」 → 승인하면 내 계정에 작은 Lambda · 기록 표(DynamoDB) · 깨우는 규칙 4개 · 로그(14일)를 만듭니다. 월 약 $0.1 미만.
- CloudWatch 경보(요청 급증 · 차단 급증 · 오류 증가) · ECS 이벤트(컨테이너 멈춤 · 헬스 체크 실패 · 태스크를 못 띄움 · 배포 실패) · 5분 확인(실행 태스크 부족 3번 연속)으로 깨어나 기록하고, 메일 · 디스코드(웹후크)로 알립니다. 같은 일은 30분에 한 번.
- 오류 · 장애 때는 **이전 버전 롤백 제안**을 준비합니다. VS Code 모니터에서 승인하거나, 급하면 알림의 일회용 링크(12시간 · 한 번만 · 되돌릴 버전 번호를 직접 입력해야 실행)로 폰에서 승인합니다. 그 사이 버전이 바뀌었으면 실행하지 않습니다.
- 감시자는 읽기 · 기록 · 알림 · 승인된 롤백(recoder:watch 표시가 붙은 서비스만)만 할 수 있습니다. 기록은 내 AWS 에만 남고 30일 뒤 지워집니다.
- 감시자 역할(recoder-watcher)은 원클릭 IAM 셋업 스택이 만듭니다(스택을 최신으로 업데이트). 직접 만들 때는 권한 안내의 「24시간 감시자 역할」을 따르고, 학교 계정은 LabRole 을 씁니다. 배포 키는 역할을 만들 수 없고 Lambda 에 넘기기만 합니다.
- 배포가 끝날 때마다 롤백 기준(이번 배포 직전 버전)을 감시자에게 알려 줍니다. 「AWS 리소스 정리」가 감시자도 찾아 먼저 지웁니다(서비스가 먼저 지워져 혼자 남은 감시자 포함).

## 2.0.46 — 2026-10-23 (Preview)

**배포 설정 시트 — 꼭 필요한 것만, 나머지는 접어서**
- 캔버스에서 ECS · S3 를 누르면 오른쪽에 새 설정 시트가 열립니다: 머리(로고 · 제목 · 한 줄 설명) → 이름 · 지역 · 버전(미리 채워 두고 「변경」으로만 고침) → 보호 두 줄(기본 방패 + 강도 고르기, 공격·장애 감지 알림 + 메일) → 유료 옵션 한 줄(HTTPS 주소 · 대규모 방패 · 관리형 DB, 켜면 펼쳐짐) → 「고급」(사양 · 포트 · 환경변수 · 실행 역할) → 맨 아래 예상 추가 요금과 버튼 하나.
- 지역은 「서울 ap-northeast-2」처럼 이름으로 보여 줍니다. 버전은 지난 배포가 v3 이면 v4 를 미리 채우고 「지난 배포 v3」를 함께 씁니다.
- 예상 추가 요금: HTTPS 만이면 월 약 $18+(로드밸런서), 대규모 방패면 월 약 $25+, 관리형 DB 는 +$15. 긴 요금 설명은 「자세히」 안으로 옮겼습니다.

**GitHub 푸시 시트**
- 저장소 검색(이름 또는 URL 붙여넣기) · 목록 · 새 저장소 만들기 → 올릴 파일(칩, 「파일 고르기」로 골라 빼기) → `.env` 같은 비밀값 파일은 자동으로 빠졌다고 한 줄로 → 커밋 메시지 → 「커밋하고 푸시」 한 번(커밋 뒤 바로 푸시 승인 단계로). 저장소를 고르지 않고 누르면 무엇이 빠졌는지 알려 줍니다.

**빠른 이동 휠**
- 같은 동작(방향키 · Shift 칸 · 편집)을 둥근 카드와 선 아이콘으로 다시 그렸고, 가운데에 리코더 캐릭터가 있습니다. 이모지는 쓰지 않습니다. 편집 중인 빈 칸도 강조됩니다.

**공통**
- 화면 부품 모음(ui/kit · ui/icons): 시트 머리 · 값 줄 · 설정 줄 · 고르기 · 접기 · 버튼 · 안내 줄 · 선 아이콘. 좁은 사이드바(420px)에서도 깨지지 않게 맞췄습니다. 캔버스 머리의 「폴더 변경」이 두 줄로 꺾이던 것도 고쳤습니다.

## 2.0.45 — 2026-10-22 (Preview)

**팀 구성 — 버튼 하나로 인원 · 역할별 모델 · 테스트**
- 입력창의 「팀 6명 · 균형」 버튼을 누르면 팀 구성 창이 열립니다: 팀 모드 켜기, 프리셋(품질 우선 · **균형(추천)** · 비용 절약 · 직접 설정), 역할(설계 · 개발 · 검토 · 테스트)마다 쓸 모델, 개발 인원(−/+), 테스트 켜기. 키가 없는 공급자는 흐리게 보이고 고를 수 없습니다(「AI 연결에서 추가」).
- 균형 프리셋은 코드를 쓰는 역할(설계 · 개발)에 품질 모델, 읽고 확인하는 역할(검토 · 테스트)에 빠른 모델을 씁니다. 고른 모델을 쓸 수 없으면 기본 공급자로 이어 갑니다.
- 요청 글로 본 추천 인원(「요청 크기 중간 · 추천 개발 3명」)과, **지난 실행 기록으로만** 낸 예상 시간 · 비용을 보여 줍니다. 기록이 없으면 지어내지 않고 「첫 실행 뒤 표시」라고 씁니다.
- 입력창 버튼을 키웠습니다(36px · 보내기 40px). 위치 칩은 「루트」 대신 열린 프로젝트 이름을 보여 줍니다.

**테스트 리코더 — 완성 기준을 실제로 시험합니다**
- 새 프로젝트를 만들면, 승인한 완성 기준(합격 조건)마다 테스트 리코더가 HTTP 시험을 쓰고 **실행 중인 앱**(생성 직후 실행 점검 컨테이너 — Docker 가 있고 ReCoder 실행 점검이 도는 Node 서버 구조일 때)에 보내 확인합니다. 시험 경로는 실제 서버 경로표와 맞춰 거르고, 확인할 수 없는 조건(화면 모양 등)은 이유와 함께 「확인 불가」로 둡니다.
- 실패한 조건은 그 요청이 거친 파일의 문제로 교정 단계에 넘기고, 고친 뒤 같은 시험을 다시 돌립니다(특정 시험 값만 맞추거나 검사를 끄는 수정은 금지).
- 결과 화면의 「완성 기준 테스트」: 「3/4 통과 · 확인 불가 1」 배지, 조건별 판정 · 시간 · 「고친 뒤 · 재시도 1」, 펼치면 요청 · 응답 근거와 1차 실패 → 2차 통과 과정. 응답의 비밀번호 · 토큰 값은 가립니다. 명세 기록 파일의 「자동 확인」 열도 채워지고, 모든 조건이 통과했을 때만 verified 로 표시합니다.
- 테스트를 끄거나 기존 프로젝트에 더한 코드는 시험하지 않고, 그 사실을 결과에 그대로 적습니다.

**AI Village — 리코더마다 무엇을 했는지**
- 진행 단계(공통 기반 → 기능 → 화면 → 전체 점검 → 테스트)와 리코더 카드: 지금 파일 · 상태 · 일한 시간 · AI 호출 · 비용(단가를 아는 호출만, 모르면 「단가 미설정」).
- 카드를 누르면 오른쪽 패널에 **코드**(완성 파일 앞부분, 비밀값 모양은 가림 — 결과가 오면 전체) · **검사**(관문 통과 · 수정 · 차단, 테스트 조건별 판정) · **기록**.
- **다시 보기:** 막대를 끌거나 ▶ 로 처음부터 — 그 시점의 카드 · 단계 · 호출 수를 다시 보여 줍니다. 끝난 뒤에는 결과 위에 접힌 「팀 작업 다시 보기」로 남습니다.

**팀 벤치마크 — 숫자로 확인**

- **OpenAI 호환 API(DeepSeek 등):** API 주소 + 키로 연결합니다. 키는 VS Code 보안 저장소에만, 주소는 https 만(내 PC 의 localhost 만 http). 강제 도구 호출을 모르는 서버면 JSON 모드로 한 번 다시 보냅니다. 기본 연결로도, 절약 등급으로만도 쓸 수 있습니다(절약용 키를 넣어도 기본 연결은 바뀌지 않음).

- **공급자 비교:** Develop › AI 공급자 · 비용에서 같은 요청을 두 공급자로 실제 코드 생성 경로에 돌려 비용·토큰·교정 횟수·남은 오류·AI 코드 보안 점수를 나란히 봅니다. 파일은 바꾸지 않고, 한 실행의 모든 호출을 고른 공급자로 고정하며, 실패해도 다른 공급자로 바꾸지 않습니다. 시작 전에 비용이 두 번 든다는 확인을 받습니다. 항목마다 더 나은 쪽만 표시하고 종합 승자는 정하지 않습니다.

- **WAF 는 CloudFront 에:** HTTPS 주소와 WAF 를 함께 켜면 WAF 를 로드밸런서가 아니라 CloudFront 에 붙입니다. 로드밸런서에 붙이면 모든 요청이 CloudFront 주소로 보여 IP 당 제한이 사용자 여럿을 한꺼번에 막았습니다. 예전에 로드밸런서에 붙인 WAF 는 CloudFront 쪽 WAF 가 전 세계에 퍼진 뒤(다음 배포) 떼고 지워, 옮기는 동안 보호가 비지 않습니다. CloudFront 에 직접 붙인 회사 WAF 는 건드리지 않습니다.
- **원본 잠금:** CloudFront 가 붙이는 비밀 머리글이 맞는 요청만 로드밸런서가 앱으로 넘기고 나머지는 403 으로 막습니다(다른 사람의 CloudFront 로 우회하는 길 차단). 이미 쓰던 HTTPS 주소는 머리글이 퍼진 뒤 다음 배포에서 잠가, 그 사이 사용자가 403 을 보지 않습니다. HTTPS 를 끄면 풉니다.
- **정리 뒤 다시 배포:** 정리로 지운 DB 접속 정보는 7일 동안 같은 이름으로 만들 수 없어 다시 배포가 실패했습니다 — 이제 되살려 씁니다.
- **방패 대응:** 2.0.26 이전 버전으로 배포한 서비스에 공격 대응(차단·강도 변경)을 적용하면 로드밸런서·CloudFront 뒤라는 설정을 잊던 것을 고쳤습니다.
- **리소스 정리:** 오래 걸리는 정리(DB·CloudFront)는 코어가 뒤에서 하고 화면은 진행 상황(몇 번째·무엇)을 보여 줍니다 — 15분을 넘겨 실패로 보이던 것을 고쳤습니다. 같은 리전 정리가 겹치면 막습니다. CloudFront 가 아직 쓰는 인증서, 만드는 중인 DB 는 실패 대신 "다음 정리 때"로 두고, DB 가 남아 있으면 그 접속 정보·서브넷 그룹도 남깁니다. S3 파일을 일부 못 지우면 그 이유를 알려 줍니다. CloudFront 에 붙인 WAF 도 찾아 지웁니다.
- **로드밸런서 위치:** 태스크가 사설 서브넷에 있어도 로드밸런서는 같은 영역의 공개 서브넷(인터넷 게이트웨이로 나가는 곳)에 둡니다. 새 로드밸런서에 WAF 를 붙일 때 최대 3분 기다리고, WAF 를 끌 때 지우기를 다시 시도하며 끝내 못 지워도 배포는 계속합니다.
- **내 도메인:** Route 53 에 이미 다른 서버를 가리키는 레코드가 있으면 덮어쓰지 않고 알려 줍니다. Route 53 오류는 배포 실패가 아니라 안내로 남깁니다. 비슷한 도메인(a-b.com·ab.com)의 인증서 요청이 섞이지 않게 했습니다.
- **권한 템플릿:** 리스너 규칙(원본 잠금), 전역 범위 WAF, 비밀 되살리기, 도메인 레코드 읽기 권한이 추가됐습니다 — 권한 템플릿 스택을 새 템플릿으로 업데이트하세요(관리형 정책 3개 그대로). 업데이트 전에는 원본 잠금이 꺼진 채 배포되고, HTTPS 주소 + WAF 를 함께 쓰는 배포는 예전처럼 WAF 를 로드밸런서에 둔 채 배포하고 업데이트하라고 안내합니다.

- 새 CloudFront 는 전 세계에 퍼지는 데 5~15분 걸립니다. 그동안 주소가 열리지 않아도 배포 실패로 보지 않고 안내만 합니다.

## 2.0.7 — 2026-10-10 (Preview)

**배포 — Docker 배포가 계속 안 되던 원인**
- 화면·서버 폴더형 Node 앱(frontend/ + backend/)은 ReCoder 가 검증한 Dockerfile 을 씁니다(생성할 때 고정 파일, 배포 화면의 Dockerfile 만들기, 깨진 Dockerfile 자동 수정). 폴더마다 설치·빌드하고, 실행 이미지에는 서버 운영 의존성과 화면 빌드 결과만, npm 없이 node 로 바로 실행합니다.

- 테이블을 별도 스크립트(npm run db:init)로만 만드는 앱도 배포가 빈 DB 에 테이블을 먼저 만듭니다(`relation "products" does not exist` 로 죽던 문제).

**보안 게이트**
- 배포를 막지 않는 권고는 게이트에 "권고 N건" 으로 붙이지 않습니다(이상 없음). 보안 화면에서는 "참고" 로 보입니다.
- 이어진 RUN 합치기(DL3059)·apk 캐시(DL3019)·실행 명령 JSON(DL3025)·숫자 USER(DL3066)·OS 패키지 근거 주석(DL3018/DL3008)을 생성 직후와 배포 직전에 같은 동작으로 정리합니다. 설명 주석 위에 남은 예외 표시가 두 번 보이던 것도 정리합니다.

**설계**
- 새 앱은 설계 결정을 넉넉히(5~8개) 묻습니다 — 주제를 먼저 받고 카드를 3개씩 나눠 동시에 받아 응답 길이 한도에 걸리지 않습니다. 기존 프로젝트 수정은 예전처럼 1~3개.

## 1.1.32 — 2026-10-09 (Preview)

**배포 — 필요한 설정 · 로컬 데모**
- 로컬 Docker 배포가 빌드하기 **전에** 앱이 시작할 때 요구하는 설정값(없으면 종료하는 환경변수)을 찾아 보여 줍니다. 예전에는 검증된 쇼핑몰 기반을 배포하면 이미지를 다 빌드한 뒤 `JWT_SECRET` 이 없어 "앱이 시작하자마자 오류로 종료됨" 으로 실패했습니다.
- 앱 내부 서명 키(`JWT_SECRET` 등)는 이 PC 의 로컬 배포용으로 자동 생성합니다. Stripe 같은 외부 키는 배포 화면의 "필요한 설정" 에서 입력합니다. 값은 `~/.recoder/deploy_settings` 에만 보관하고 이미지·프로젝트 파일·배포 기록·화면 응답에는 남기지 않으며, 실행할 때만 컨테이너에 넘깁니다. PC 의 `.env` 에 있는 값은 그대로 씁니다.
- 키가 없으면 **[키 없이 결제를 끈 로컬 데모로 실행]** 을 누르면 됩니다. 모의 결제 서버를 앱 이미지로 함께 띄우고 데모 상품을 넣습니다. 상품·장바구니·주문을 써 볼 수 있고 주문은 잠시 뒤 '결제 완료(테스트)' 가 됩니다. 실제 카드 결제는 일어나지 않습니다. [실제 키로 실행하기] 로 언제든 되돌립니다.
- 필요한 설정이 비어 있으면 승인 버튼이 잠기고, 실행 요청이 와도 빌드 전에 멈춥니다(기존 컨테이너는 그대로).
- 설정값이 없어 종료한 실패는 "코드를 고치라" 대신 "앱에 필요한 설정값이 비어 있음" 으로 안내하고 [필요한 설정 입력하고 다시 배포] 를 보여 줍니다. 이 경우 코드를 바꾸는 [문서 근거로 오류 수정] 은 숨깁니다(안전장치를 지우는 수정을 막기 위해).
- 실패 후 이전 컨테이너 복구·롤백도 같은 설정값으로 다시 띄웁니다.
- 앱 폴더 안의 `backend/src/schema.sql` 같은 DB 초기화 파일도 찾아 빈 DB 에 테이블을 만듭니다.

## 1.1.19 — 2026-09-27 (Preview)

실기기 쇼핑몰(React client/ + Express server/) 프로젝트의 로컬 Docker·S3 배포 실패를 고쳤습니다.

**로컬 Docker**
- package.json 의 의존성 버전이 npm 에 실제로 있는지 배포 계획에서 확인합니다. 없는 버전(예: `jsonwebtoken@^9.1.2`)은 빌드 전에 오류로 알리고, 자동 수정이 같은 major 의 최신 버전(`^9.0.3`)으로 고칩니다. 예전에는 몇 분 빌드한 뒤 `npm error ETARGET` 으로 멈췄습니다. 오프라인이면 이 확인은 건너뜁니다.
- AI 코드 생성도 새 package.json 의 버전을 같은 방식으로 확인해 교정을 요청합니다.
- `build` 가 `cd client && npm run build` 처럼 하위 폴더에서 빌드하면, Dockerfile 이 그 폴더 의존성을 설치하도록 자동 수정(새로 만드는 Dockerfile 에는 처음부터 포함)합니다. 빌드 도구는 실행 이미지에 남기지 않습니다. 예전에는 버전 문제를 고쳐도 다음 단계에서 `react-scripts: not found` 로 멈췄습니다.
- 빌드한 화면(client/build)을 서버가 제공하지 않으면 알려 주고, 자동 수정으로 Express 서버가 그 화면을 제공하게 합니다(원본은 .recoder/backups). 예전에는 컨테이너가 떠도 브라우저에서 화면이 나오지 않았습니다.
- `client/` 코드가 불러오는 react·axios 를 루트 package.json 기준으로 "선언되지 않은 패키지"로 잘못 막던 문제를 고쳤습니다. 각 폴더의 package.json 기준으로 봅니다.
- 앱이 localhost 의 PostgreSQL·MySQL·MongoDB·Redis 에 연결하면 "컨테이너 안에는 DB 가 없다"는 경고를 보여 줍니다.
- 빌드 실패 진단: 없는 버전(ETARGET)·없는 패키지(404)와 `sh: line 1: … command not found` 를 원인대로 설명합니다.

**S3 정적 배포**
- React·Vite·Vue 등 빌드가 필요한 프런트엔드(루트 또는 client/·frontend/ 등)를 찾아 배포 준비 때 `npm install` → `npm run build` 를 실행하고 산출물(client/build 등)을 올립니다. PC 에 npm 이 없으면 Docker 로 빌드합니다. 소스맵은 만들지 않습니다. 예전에는 빌드 전 템플릿(client/public/index.html)을 올려 제목만 있는 흰 화면이 떴습니다.
- 빈 `<div id="root">` 만 있고 스크립트가 없는 HTML 은 "빌드 전 템플릿"으로 보고 올리지 않습니다.
- 화면이 API 서버를 호출하면 승인 카드에 "S3 에는 화면만 올라가 API 기능은 동작하지 않는다"고 알려 줍니다.
