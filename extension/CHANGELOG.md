# Changelog

## 1.1.13 — 2026-09-26 (Preview)

- 보안 게이트가 이미지의 치명적(CRITICAL) 취약점으로 배포를 막으면 "CRITICAL 1건" 대신 **어떤 패키지·버전이 어디서 왔고 어떻게 고치는지**를 보여 줍니다(베이스 이미지 OS 패키지 / 베이스 이미지의 npm / 앱 의존성 구분). 차단 동작과 기존 컨테이너 보존은 그대로입니다.
- 배포 준비 점검: `sqlite3` 5.x 처럼 보안 검사에서 배포가 막힐 것이 확실한 의존성을 빌드 전에 알리고, lock 파일이 없으면 버튼으로 안전한 버전(^6.0.1)으로 올립니다. 코드 생성도 이런 버전을 쓰지 않습니다.
- Deploy 상단에 **폴더 변경** 버튼을 추가했습니다. 폴더 하나로 연 창에서도 워크스페이스의 다른 폴더를 고르거나 새 폴더를 추가해 바로 전환합니다. 명령 팔레트 `ReCoder: 배포할 프로젝트 폴더 변경`도 같습니다.
- GitHub 연결에서 **새 공개 저장소**를 만들 수 있습니다(기본은 여전히 비공개). 공개 저장소를 고르면 공개 범위 안내를 보여 줍니다.
- Discord: **내가 만든 봇의 토큰**으로 바로 연결합니다. 별도 봇 프로그램(127.0.0.1:8765) 없이 서버·채널을 고르고 테스트·배포 알림을 보냅니다. 토큰은 VS Code 보안 저장소에만 저장하며, 초대 링크는 알림에 필요한 최소 권한(채널 보기·메시지 보내기·링크 첨부)만 요청합니다. 기존 웹후크·봇 서버 방식은 그대로 쓸 수 있습니다.

## 1.1.12 — 2026-09-26 (Preview)

- 로컬 Docker 배포 **배포 준비 점검**: 빌드 전에 프로젝트 설정을 읽어 확정적으로 실패할 항목을 보여 줍니다 — 없는 파일을 가리키는 빌드 스크립트(예: src/ 없는 react-scripts), 선언되지 않은 패키지, 없는 시작 파일, 앱 포트와 Dockerfile 포트 불일치, 비root 컨테이너가 쓸 수 없는 작업 폴더(SQLite), 없는 헬스 경로, .dockerignore 누락. 포트·헬스 경로·작업 폴더 권한·.dockerignore·쓰지 않는 빌드 스크립트는 버튼으로 고칩니다(원본은 프로젝트의 .recoder/backups 에 보관).
- 빌드·실행 실패 시 마지막 줄 대신 **실제 원인 줄과 해결책**을 보여 줍니다(모듈 없음, lock 파일 불일치, 네이티브 모듈 컴파일, 베이스 이미지 받기 실패 등). 컨테이너가 시작 직후 종료된 경우도 앱 로그로 진단합니다. ECS 빌드 실패에도 같은 진단을 씁니다.
- Dockerfile 생성: `const PORT = 5000` 형태의 포트를 읽고, 헬스 라우트가 없으면 앱이 실제로 200 을 주는 경로(/ 또는 FastAPI /docs)로 확인합니다. AI 없이 템플릿으로 만들 때도 프로젝트의 포트·진입점을 씁니다. 서버 스택도 .dockerignore 를 함께 만들고, 비root 사용자가 작업 폴더에 데이터 파일을 만들 수 있게 합니다.
- 코드 생성 결과 검증: 적용하면 빌드·실행이 깨지는 결과(쓰지 않는 빌드 스크립트, 선언 안 된 패키지 등)는 AI 에 한 번 교정을 요청하고, 그래도 남으면 결과에 "확인 필요"로 표시합니다.

## 1.1.11 — 2026-09-26 (Preview)

- **변경 필요:** 설정 `recoder.gateway.url` 의 기본값을 비웠습니다. 기본 동작은 본인 AWS 계정(BYO)입니다. 수업·팀 게이트웨이를 쓰던 경우 운영자에게 받은 주소를 이 설정에 넣고 `ReCoder: Restart Core` 를 실행하세요. 이미 등록한 토큰은 보안 저장소에 남아 있어 다시 등록할 필요가 없습니다.
- 마켓플레이스 Preview 게시 준비: Preview·무료 표시, 신뢰할 수 있는 워크스페이스에서만 실행(제한 모드·가상 워크스페이스 미지원)을 매니페스트에 명시했습니다.
- README를 마켓 상세 페이지용으로 정리하고, 기기 밖으로 나가는 데이터(AI 요청·배포·GitHub·Discord)와 자격증명 저장 위치를 고지했습니다. 텔레메트리는 수집하지 않습니다.
- Linux x64 배포본을 추가했습니다. 릴리스 워크플로가 Windows·Linux VSIX를 각각 빌드하고 설치본 스모크를 수행합니다.
- 설치본 스모크가 VSIX의 파일 권한을 버려 Linux에서 번들 Core를 실행하지 못하던 문제와, 실패 시 로그 보관 폴더가 없어 실제 오류를 가리던 문제를 수정했습니다.
- AWS 없이 AI 사용: Claude(Anthropic) 또는 ChatGPT(OpenAI) API 키로 연결할 수 있습니다. 키는 VS Code 보안 저장소에만 두고, 명시적으로 고른 경우에만 사용합니다. 기존 AWS·게이트웨이 경로는 그대로입니다.
- Deploy 보안 게이트: 보안 화면에서 돌린 검사 결과를 게이트에 반영합니다. 이상 없음은 초록, 발견 항목이 있으면 빨강, 검사하지 못한 항목이 있으면 노랑입니다. Dockerfile·이미지가 아직 없는 검사는 "해당 없음"으로 표시합니다.
- 워크스페이스에 새 프로젝트 폴더를 추가하면(코드 생성 대상 폴더 포함) Deploy가 그 프로젝트를 보여 줍니다. 이전 프로젝트의 소스 분석·승인 카드·검사 결과는 비웁니다. 폴더가 여러 개면 상단에서 고를 수 있습니다.
- Discord: '봇 서버 불러오기'가 실패해도 기존 웹후크 연결·알림이 계속 동작합니다. 봇 실행 안내(Windows `run.ps1`)와 토큰·Intent 오류 안내를 추가했습니다.
- AWS 미연결 안내 문구에서 내부 API 경로를 없앴습니다.

## 1.1.7 — 2026-09-25

- Bedrock의 일시 장애를 재시도하고, 설정되지 않은 Gemini 오류가 실제 실패 원인을 가리던 문제를 수정했습니다. 인증 오류는 불필요하게 반복하지 않으며, 설계 생성 오류와 대기 시간을 정리했습니다.
- React 플러그인이 있는 일반적인 Vite 설정을 서버 프로젝트로 잘못 분류하던 문제를 수정했습니다. 정적 빌드 결과를 확인한 뒤 nginx로 실행하므로 존재하지 않는 index.js를 실행하지 않습니다.
- 컨테이너 시작 명령만 성공하고 앱이 종료·재시작하는 경우 배포를 실패로 판정합니다. 이전에 검증된 컨테이너가 있으면 복구하고, 아직 HTTP 응답이 없는 실행은 검증 대기로 표시합니다.
- hadolint JSON 실행·검증과 Trivy 캐시를 보완했습니다. 스캔 결과가 없을 때 불필요한 AI 요약을 생략하고, 요약이 지연돼도 실제 검사 결과를 표시합니다.
- Docker Desktop의 부가 정보 조회가 멈추면 실행 중인 엔진도 꺼졌다고 오판하던 준비 검사를 서버 버전 조회로 교체했습니다.
- 정적 프런트엔드 런타임을 만들 때 Alpine 패키지 보안 업데이트를 적용합니다. 기존에 생성한 정적 Dockerfile의 포트·헬스 검사 인식은 유지합니다.

## 1.1.2 — 2026-09-24

- 로컬 배포에서 사용자가 지정한 포트, 환경변수, 프로젝트 정보와 감시 설정을 실제 실행·이력·롤백까지 유지합니다.
- 재빌드한 이미지를 다시 검사하고 검사한 이미지 ID로 실행합니다. 검사 차단 뒤 재시도로 검사를 건너뛰지 않으며, 새 검사 오류는 승인 상태에 따라 재확인을 요구합니다.
- Docker 멀티스테이지의 최종 런타임 포트를 감지해 ECS 설정에 반영합니다. 생성한 React 정적 이미지의 포트 불일치는 AWS 변경 전에 차단하며 ECS 헬스 체크는 nginx 런타임의 wget을 사용합니다.
- 로컬 Next.js·서버 앱의 실제 헬스 경로를 감지하고, 한국어 Windows 빌드 로그와 긴 빌드·검사 응답 대기를 수정했습니다.
- React 정적 Dockerfile 저장 승인에 기본 .dockerignore 생성을 안내하고 함께 생성합니다. 기존 제외 규칙은 유지합니다.
- 비어 있거나 손상된 Trivy·Gitleaks 보고서와 Hadolint 실행 실패를 검사 통과로 처리하지 않습니다.
- S3 업로드 전에 빌드하지 않은 CRA/Vite 진입 파일을 찾아 빌드 산출물 선택을 안내합니다.
- GitHub·Discord 연결과 이전 1.1.1의 개선을 모두 포함합니다.

### 안전장치
- 보안 스캔 미실행은 "통과"가 아니라 "확인 못 함"으로 표시하고 승인 강도를 올림.
- 빌드 전 이미지를 Trivy 에 넘기지 않음 — 실행 시점(빌드 후) 1회 스캔 보장, CRITICAL 차단.
- 배포 허용 조건은 OPA 정책(.rego) 한 곳에 선언 — 판정 불능이면 차단(fail-closed).
- 에이전트 로드 실패가 200 OK 로 위장되던 응답 제거(503 + 사유).
- LLM 라우터 단일화 — 서킷브레이커·게이트웨이·비용 집계가 전 경로에 적용.
