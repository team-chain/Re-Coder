# 배포 캔버스

Deploy 탭에 프로젝트 단위 캔버스를 추가했다. 기존 `DeploymentCenter.tsx`와 ECS/S3 배포 실행 코드는 유지한다. 캔버스 우측 **•••** 메뉴를 펼치면 **상세 배포**, **이력·롤백**, **AWS 연결**, **Docker**, **보안** 및 **Discord**를 사용할 수 있다. Develop와 기존 채팅·코드 수정 흐름도 그대로 유지한다.

홈의 Deploy 카드 및 상단 Deploy 탭(`hub:deploy`)에서 캔버스를 바로 표시한다. 기존 배포 센터 진입 주소(`deploy`)도 같은 화면을 연다. 기존 **운영 대응**은 캔버스 도구 모음에서 접근하며 AI·AWS 준비 조건을 유지한다.

Workspace는 드래그 중심 배포 캔버스로 시작한다. 기본 화면은 프로젝트, 보안 게이트, 배포 대상 4개와 연결된 Discord를 이전 참고 이미지의 입체 배치로 표시한다. 프로젝트를 대상으로 끌어 놓거나 대상을 클릭하면 오른쪽 설정 패널이 열린다. ECS는 서비스·태그·리전만 먼저 표시하고 나머지 값은 고급 설정에서 수정한다. **배포 내용 확인 → 승인** 후 기존 실행 경로로 이어지며, 드롭만으로 배포하지 않는다. 프로젝트 클릭은 소스 분석을 연다.

Develop · Deploy · Security 전환은 공통 상단에 고정한다. Develop는 전체 영역을 누를 수 있는 2×2 카드, 좁은 화면에서는 한 열이다. 홈은 세 작업 카드를 같은 비중으로 표시한다. Security는 한 번의 검사 시작 버튼과 접힌 결과 세 항목으로 구성한다. 기존 개별 검사와 정책 원문은 각 항목을 펼쳐 접근한다. 검사 응답은 요청 ID로 구분하며, 메뉴를 옮겨도 진행 중인 검사와 배포 화면을 유지한다.

AWS 연결은 공통 상단에서도 열 수 있다. 기존 프로필·배포 전용 역할·브라우저 온보딩·키 입력 기능은 유지하고 추가 방법과 정책 원문은 접어서 표시한다. 배포 완료 시 캔버스 아래에 **서비스 열기**를 바로 제공한다.

**•••** 메뉴에 상세 구조·보안 레이어·2D·크기 조절을 모았다. 검사 기록·ECS 계층·이미지 정보는 **배포 상태** 패널에서, 분석 결과와 파일 열기는 **분석 상세**에서 확인한다. 보안 차단과 롤백 승인 요청은 기본 화면에 표시한다. 로고를 누르면 기존 작업 선택 홈을 연다. **AI와 대화**는 닫아도 입력과 응답을 유지하며 새 응답을 버튼에 알린다. 연결 상태 버튼에서 진단과 사용량을 확인한다.

## 화면과 동작

| 화면 | 구현 |
| --- | --- |
| R01 | AWS 미연결 상태에서도 ECS/S3 노드를 표시한다. 잠긴 대상에는 드롭할 수 없고 클릭하면 AWS 연결 화면으로 이동한다. |
| R02 | 현재 프로젝트의 배포 기록, AWS 조회, Git 원격에서 계정·리전·클러스터·서비스·버킷·저장소 이름을 가져온다. 아직 생성되지 않았거나 조회하지 못한 리소스에는 가짜 이름을 표시하지 않는다. |
| R03 | 프로젝트 전체를 드래그하면 가능한 대상에 링이 나타난다. 키보드 또는 클릭으로도 같은 설정과 승인 절차를 열 수 있다. |
| R04 | ECS의 리전·계정·사양·현재 태스크 정의와 이미지 digest·조회 가능한 AWS 예산을 보여준다. S3는 실제 폴더·업로드 목록·제외 파일·공개 범위를, GitHub는 브랜치와 커밋을 보여준다. |
| R05 | 저장된 소스·이미지 검사 단계와 서버 정책 결과를 표시한다. 대기·미실행·미확인·발견 항목·통과를 구분한다. |
| R06 | 차단 사유·수정 제안·기존 AI 수정 진입점을 제공한다. 기존 서버의 차단과 롤백 승인 정책을 그대로 적용한다. |
| R07 | AWS에서 조회한 Cluster → Service → Task와 실제 희망/실행 수, 태스크 ID, 상태, 이미지 digest를 표시한다. 최대 100개 태스크를 조회하며 그림에는 처음 4개, 목록에는 조회된 전체를 표시한다. |
| R08 | 시크릿 탐지 근거와 잠재적 유출 경로를 점선으로 표시한다. 실제 ECS에 연결된 internet-facing 로드 밸런서는 별도로 표시한다. |
| R09 | 기존 `analyzeProject()`의 파일·import 관계와 고립·과부하 결과를 시각화한다. 45개를 넘는 프로젝트는 폴더로 묶고 검색과 폴더 진입으로 모든 파일에 접근한다. |
| R10 | 기존 `analyzeFile()`의 함수·호출 관계를 표시한다. 상위 탐색과 파일 열기를 제공한다. |
| R11 | 기존 Discord 봇/Bridge의 서버·채널 선택 및 연결을 사용한다. 사용자가 알림을 켜면 이 화면에서 관측한 새 배포·게이트·롤백 이벤트를 전송한다. 중복과 멘션을 방지한다. |

Three.js와 SVG 로고는 웹뷰 번들 안에 포함된다. Three.js의 입체 돌출 받침, 조명, 게이트 다면체, 곡선 연결선과 방향 화살표를 렌더링하며 DOM 버튼을 같은 좌표에 맞춰 클릭·드롭·키보드 접근을 유지한다. WebGL 실패, 컨텍스트 소실 또는 사용자의 2D 선택 시 SVG로 표시하고 컨텍스트 복원 시 다시 그린다. 크기 변경에 맞춰 렌더링하며 종료 시 geometry·material·renderer를 정리한다. 80개 초과 노드는 2D로 전환한다. 캔버스가 580px 이하로 좁아지면 읽을 수 있는 대상 목록으로 전환하며 같은 동작을 제공한다.

## 실행 경로 보존

- ECS: 기존 `workspace.deploy.ecs` → `/api/deploy/ecs` 실행 경로. 기존 사전 검사·권한 확인·정책 게이트·파이프라인·헬스 체크·승인 롤백을 사용한다.
- S3: 기존 `workspace.deploy.s3`와 SSE 업로드, 경로 제한, 민감 파일/비정적 파일 제외, 파일 수 제한을 사용한다. 승인 전 선택한 파일의 내용 해시를 저장하고 실행 직전에 다시 비교한다.
- GitHub: 기존 푸시 API에 `auto_commit: false`, `force: false`를 보낸다. 기존 호출자의 자동 커밋 기본값은 변경하지 않는다. 푸시 전 실제 gitleaks 결과를 확인한다.
- Docker: 기존 ShipMode의 빌드·실행·승인·복구 흐름으로 연결한다.
- 승인 계획은 웹뷰별로 격리하고 한 번만 사용한다. 취소·새 계획·유효 시간 만료·워크스페이스/Git 상태/계정 변경 시 이전 승인을 사용할 수 없다. 확인된 ECS 태스크 정의가 변경되면 재승인을 요구한다.

새 Core API `GET /api/deploy/canvas`와 `/api/deploy/canvas/target`은 조회만 수행한다. 프로젝트 경로에 해당하는 배포 기록만 선택하며 다른 프로젝트의 이력을 가져오지 않는다. 새 Discord 이벤트 경로는 기존 등록 키 인증과 봇 채널 연결을 사용한다.

## 실제 데이터가 없는 경우

- 예산·이미지 digest·리소스·검사 결과의 조회 실패를 성공이나 0으로 바꾸지 않는다. 경고 또는 미확인으로 표시한다.
- 참조 그림의 `하드코딩 키 → 커밋 → 실행 이미지 → 공개 ALB` 전체 연결을 입증하는 데이터는 기존 Core에 없다. 소스 스캔만으로 커밋·이미지 포함이나 실제 인터넷 도달을 확정하지 않는다.
- 현재 ECS API에는 차단을 두 번 확인하여 우회하는 경로가 없다. 캔버스에서 우회 API를 새로 만들지 않았으며, 기존 도구의 승인 기능은 유지한다.
- Discord 알림은 캔버스가 열려 있는 동안 관측한 이벤트에 한정한다. 켜기 전 이력은 소급 전송하지 않는다.
- AWS 계정 연결만으로 모든 계정 리소스를 나열하지 않는다. 현재 프로젝트에서 알려진 서비스와 프로젝트 식별자에 해당하는 S3 버킷을 조회한다.

## 검증 및 로컬 미리보기

외부 배포 없이 승인·취소·중복 방지·변경된 승인 무효화·잠금·실데이터 매핑·폴더 집계·S3 파일 변경·GitHub 푸시 옵션·Discord 이벤트 인증/중복 방지를 테스트한다.

```powershell
cd extension
npm run build
npx tsc -p webview-src/tsconfig.test.json
node --test webview-tests/canvas.test.js
npx webpack --config harness/canvas-preview.config.js
node harness/serve-canvas-preview.js
```

`http://127.0.0.1:4179`는 격리된 UI 픽스처다. AWS·GitHub·Discord에 요청하지 않으며 위쪽 버튼으로 잠금/연결/검사/차단/완료 상태를 선택한다. 실제 배포 검증으로 간주하면 안 된다.

`http://127.0.0.1:4179/?layout=workspace`는 실제 Workspace 레이아웃과 라우터를 사용한다. 홈의 Deploy 카드와 상단 탭을 통해 캔버스로 진입하는 경로를 검증할 때 사용한다.

브라우저에서 프로젝트 드래그 → 승인/취소, 차단 및 보안 레이어, 파일 → 함수, 2D 보기, ECS 계층, S3 승인 및 결과 URL, Discord 이벤트 상태, 300px 사이드바를 확인했다. 실제 AWS 신규 배포와 Discord 채널 전송은 이번 변경 검증에서 수행하지 않았다.

### 2026-09-23 검증 결과

- 프로덕션 웹뷰 번들 및 확장 TypeScript 빌드 통과.
- 웹뷰: 339개 통과, 기존 조건부 건너뜀 1개. Windows에서 실행할 수 없는 기존 `?` 파일명 테스트와 권한이 필요한 심볼릭 링크 테스트 2개는 제외했다. 신규 캔버스 단위/통합 테스트 19개는 모두 통과했다.
- Core: 캔버스, ECS 진행/헬스/파이프라인/빌드/실행 역할, 배포 이력, S3 API/스트림/파일 필터, Trivy/OPA, 세션 인증 관련 550개 중 547개 통과, 기존 조건부 건너뜀 2개. POSIX `0600` 모드를 검사하는 기존 이력 저장 테스트 1개는 Windows에서 실패한다. 저장·복원 데이터 비교는 통과하고 모드 비교에서만 실패했다.
- 초기 Core 실행에서 나온 인코딩/임시 폴더 문제 2개는 `python -X utf8`와 Git 저장소 밖 `--basetemp`로 재실행하여 통과했다. 제품 코드나 기존 테스트를 변경하여 감추지 않았다.
- `git diff --check` 통과. 기존 `DeploymentCenter.tsx`, ECS 실행/호환 API, S3 실행 API는 변경하지 않았다.

Core 테스트는 UTF-8 모드와 저장소 밖 임시 경로를 권장한다. 저장소 안의 임시 폴더는 `git`이 상위 저장소의 브랜치를 찾기 때문에 “Git 저장소가 아닌 폴더” 테스트의 전제를 깨뜨린다.

추가 검증에서 지연된 조회 응답의 무한 대기, 완료 상태의 역전, S3 절대경로 해석 불일치를 수정했다. 세부 검증 범위와 실행 한계는 [검증 기록](deployment-canvas-verification.md)에 정리했다.
