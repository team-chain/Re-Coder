## 2. 회차별 상세

### 🔵 회차 1 — AI-DLC 개발 단계 (로컬) · ~7/27
**목표:** "채팅 → 설계 선택지 카드 → 코드 + 근거(ADR) 생성"이 로컬에서 동작. AWS 불필요라 즉시 착수.

| 태스크 | 오너 | 완료 조건(DoD) |
|---|:--:|---|
| 스프린트0 — DoD 팀 합의 + 회차 태스크 확정 | ⬛ | DoD 7항 문서화 |
| 결정 카드 UI (채팅 + 팝업, 확정 목업 v2) | 🟩 | 선택 후 "이 선택으로 생성" 흐름 동작 |
| `CodeAgent.tsx`에 결정 단계 통합 | 🟩 | 개발 요청 시 카드가 먼저 뜸 |
| `POST /api/code/plan` — 코드 대신 결정 목록 반환 | 🟦 | 요청 시 질문·선택지·트레이드오프 반환 |
| `generate`에 결정 주입 + **ADR 영속화**(`docs/adr/`) | 🟦 | 코드 + ADR(근거·검토한 대안) 동시 산출 |
| 항상 선택지(D5)·사람 승인(D6) 반영 | ⬛ | 사소한 변경도 카드, 승인 후 실행 |
| **회차말 데모** | ⬛ | AWS 없이 "요청→선택지→코드+근거" 시연 |

### 🔵 회차 2 — BYO 연결 + 실제 배포 · ~8/10
**목표:** "AWS 연결(BYO) → 앱 종류 감지 → 배포 위치 선택 카드 → 실제 배포(S3/ECS)".

| 태스크 | 오너 | 완료 조건(DoD) |
|---|:--:|---|
| 자격증명 연결 UX (액세스 키 입력) | 🟩 | 사용자가 키 등록 → 연결 완료 표시 |
| SecretStorage(금고) 보관 | 🟩 | 키가 평문 파일로 안 남음 |

| ECS Fargate 배포 경로 완성·검증 | 🟦 | 서버형 앱이 사용자 AWS ECS에 실제 기동 |

## 3. MVP 최종 수용 기준 (9/11에 전부 ✅ = 완료)

- [ ] **개발:** 채팅 요청 시 설계 선택지 카드가 먼저 뜨고, 선택 후 코드 + ADR이 함께 생성됨
- [ ] **자격증명:** 사용자가 AWS를 최소권한 키로 연결, 키는 금고에 보관, 등록 시 점검됨
- [ ] **검사:** Preflight + 시크릿 + 이미지 취약점 스캔이 배포 전 동작, 실패 시 차단
- [ ] **배포:** 앱 종류 감지 → 선택 카드 → 사용자 AWS에 실제 배포(S3/ECS Fargate)
- [ ] **감시:** 배포 후 CloudWatch로 헬스·에러율·p95 감시
- [ ] **롤백:** 이상 감지 → 롤백 제안 → 사람 승인 → 이전 버전 복귀 (1회 리허설 완료)
- [ ] **비용:** 배포 전 예상 비용 안내 + 예산 알람 가이드
- [ ] **배포(확장):** 마켓플레이스 게시(또는 VSIX) 가능
- [ ] **보안:** 최소권한 적용 + 의존성 취약점 해소
- [ ] **품질:** 각 태스크 DoD 충족, 결정마다 ADR, 스프린트·칸반으로 추적

## 4. 진행 원칙 (2인·짧은 마감)

1. **트랙 병렬:** 인프라·백엔드(이동규) ↔ 확장·AI-DLC(윤세빈)는 의존이 적어 동시 진행. 회차말 통합 지점만 맞춤.
2. **DoD 강제(D20):** "코드 됐음"이 아니라 완료 조건 충족해야 Done. 🟡 미검증 적체 방지.
3. **스코프 방어:** 봇·조직관리 서버·EKS·완전자동롤백 등은 이번 릴리스 제외. 지연 시 회차4의 하드닝·마켓 준비를 회차5로 미룸.
4. **버퍼 사수:** 회차5는 개발이 아니라 안정화·발표. 신규 기능 금지.
5. **정체성 유지:** BYO·최소권한·금고·이미지 스캔·의존성 취약점 정리 = "배포 후 보안·안정성" 실증.
