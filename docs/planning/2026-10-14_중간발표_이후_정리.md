### 2.0.22 핵심
- AI가 만든 앱이 `getEnv('JWT_SECRET')`처럼 함수로 환경변수를 읽으면, ReCoder가 필요한 값을 몰라 실행 점검과 배포에 넣지 않았다.
  - 앱이 시작 즉시 종료되고, AI는 코드 문제로 알고 6회까지 헛수정했다. 생성 직후 "전체 점검 … 고치는 중" 반복의 원인이다.
- 수정 내용:
  - 접근 함수(`getEnv`, `requireEnv` 등)와 설정 스키마(zod, envalid)의 필수 값·최소 길이를 감지한다.
  - 서명 키처럼 만들 수 있는 값은 자동 생성해 넣는다.
  - 앱이 "X is required"로 멈추면, 만들 수 있는 값은 만들어 재시도한다. 사람이 넣어야 하는 값은 코드 교정이 아니라 "배포할 때 넣을 설정"으로 안내한다.
- 검증:
  - 전체 테스트 2698개 통과.
  - 테스트 앱을 실제 Docker로 띄운 실행 점검 통과.
  - 생성된 앱(Prisma 사용) 자체는 작업 환경에서 Prisma 엔진을 받을 수 없어 끝까지 띄워 보지 못했다.

### VSIX 빌드 (PC에서 직접)
GitHub Actions의 Build release는 기본 브랜치(main)에 빌드 설정 파일이 없어 지금은 실행 버튼이 보이지 않는다. develop을 main에 병합하기 전까지는 PC에서 빌드한다.
```powershell
python -m venv .venv-release
.\.venv-release\Scripts\python.exe -m pip install -r core\requirements-release-win32-x64.txt
npm ci --prefix extension
.\.venv-release\Scripts\python.exe scripts\build-release.py
code --install-extension extension\dist\recoder-2.0.22-win32-x64.vsix --force
```

## 2. 앞으로의 방향 (3축)
1. **현재 기능 동작 전체 안정화**: 시연 시나리오가 팀원 누구의 PC에서나 같은 결과로 끝까지 통과
2. **배포 고도화**: ECS 배포를 "시연용"에서 "운영 가능" 수준으로
3. **보안 안정성 및 옵저버빌리티를 통한 간편 운영 지원**: 배포 후 문제가 생기면 ReCoder가 먼저 알리고 원인까지 보여 줌

### 사용자별 AI(BYO) 구조에서 가능한가
- 위 개선 대부분은 AI를 부르지 않는 자동 검사·설정이라, 누구의 AI를 쓰든 똑같이 동작하고 추가 비용이 없다.
- 사용자마다 AI 모델이 달라 생성 품질이 들쭉날쭉해도, ReCoder의 검사가 결과 품질을 같은 기준으로 맞춘다.
- AI를 더 쓰는 기능(보안 자동 수정, AI 가상 사용자 등)은 켜고 끌 수 있게 하고 예상 비용을 보여 준다.
- 사용자끼리 배우는 기능은 중앙 서버가 필요하다. 당분간은 개발팀이 실제 실패를 모아 자동 수정 규칙으로 배포하는 방식(2.0.22처럼)으로 간다.

## 5. 포지셔닝
- 대기업 코드 에이전트(Claude Code, Copilot, Cursor)는 코드까지, 앱 빌더(Replit, Lovable, v0)는 자기 플랫폼 호스팅까지만 한다.
- ReCoder는 **"AI가 만든 결과물을 검증하고, 내 클라우드에 배포하고, 운영까지 책임지는 도구"**로 내세운다.
- 강점:
  - "됐다"고 말하기 전에 실제로 빌드하고 띄워서 사용자 흐름까지 확인한다.
  - 사용자 본인의 AWS에 배포하고, 코드도 사용자 PC에 남는다.
  - 배포 전에 보안·정책·승인 관문을 거친다.
  - 설계 결정을 기록(ADR)으로 남긴다.
  - 한국어, 한국 법규, 초보·학생을 대상으로 한다.
- 대기업 도구와 경쟁하지 않고, 대기업 도구가 만든 코드를 받아 검증·배포·운영하는 구조(MCP 연동)가 가장 유리하다.

## 6. 보류(킵)한 아이디어

### 마을 확장
- **날씨로 보는 운영:** 맑음 = 정상, 비 = 오류 증가, 폭풍 = 장애. 생성 후에도 마을이 운영 화면으로 남는다.
- **야간 근무:** 사용자가 없는 동안 점검·취약점 탐색·개선안 준비. 적용은 하지 않고 아침에 승인 대기 카드로 남긴다.
- **리코더 성장:** 교정에 성공한 사례가 리코더별 기억으로 쌓이고 레벨로 표시된다.
- **말 걸기·촌장 개입:** 리코더를 클릭해 질문하거나, 카드 담당을 바꾸거나, 멈추게 한다.
- **되감기와 평행 마을:** 리플레이 중 다른 선택으로 갈라져 결과를 비교한다.

### 기타
- **MCP 배포 관문:** 외부 AI 에이전트의 배포 요청을 ReCoder가 점검·승인 후 처리한다.
- **AI 가상 사용자:** 앱 설계 문서로 사용자 시나리오를 자동으로 만들고, 실제 브라우저로 사용해 본다.
- **AI 해커 vs 방어팀:** 연습용 환경에서 공격과 패치를 자동으로 주고받는다.
- **ReCoder Bench:** 앱 종류별로 모델의 "배포까지 성공률"을 겨루는 공개 리더보드.
- **체험 모드:** 무료 AI API(Groq, OpenRouter, Gemini 등)로 키 없이 작은 데모를 생성한다. 메인 생성에는 양·품질·개인정보 문제로 부적합하다.
- **트래픽 방어:** 1초 수만 건 요청 같은 대규모 폭주는 서버 앞단(CDN·WAF)에서 막아야 한다. AWS WAF, Cloudflare, Google Cloud Armor 등이 가능하다. 소·중규모는 nginx·CrowdSec 보조 컨테이너로 어디서든 막을 수 있다.

## 7. 확인된 사실
- GitHub의 무료 AI API(GitHub Models)는 2026년 7월 30일에 완전히 종료됐다. GitHub은 대안으로 Microsoft Foundry와 GitHub Copilot을 안내한다.
- ReCoder 게이트웨이는 만들어 뒀지만 현재 사용하지 않는다(확장의 게이트웨이 주소 기본값이 비어 있음). 학생 배포에 쓰려면 사용량 한도·비용 상한을 다시 정하고, API Gateway의 30초 요청 제한에 대응해야 한다.
- 보조 컨테이너(DB, 모의 결제)는 배포한 곳에 함께 뜬다. Local Docker는 사용자 PC, ECS는 AWS 태스크 안이다.
- 지금 ECS 배포는 공인 IP로 바로 노출되고, 앞단 방어(WAF 등)와 요청 급증 알람이 없다.
