# ReCoder — 포지셔닝 v2 (보안·배포 안정성 중심)

> 팀 확정 방향: **DevOps 오케스트레이션은 MCP로 누구나 붙일 수 있는 커머디티 → 해자(moat)가 아니다. 차별점은 보안 + 배포 안정성.**
> 표기: 🟢 현재 구현·검증 / 🔭 설계서 v10 로드맵(코드 일부 존재).

---

## 0. 한 줄 포지셔닝 (재정의)

> **"ReCoder는 바이브 코딩으로 만든 결과물을 ‘안전하게’ 검증·배포·운영하는 보안 안전망이다."**

- 바이브 코딩 = **빠르게 만든다.**  ReCoder = **그걸 안전하게 내보낸다.**
- Copilot/Cursor/바이브 툴과 "누가 코드를 더 잘 쓰나"로 싸우지 않는다. **그들의 출력(생성물)을 안전하게 만드는 레이어**다.

---

## 1. 시장 흐름 — 바이브 코딩의 부상 (왜 지금)

자연어 한 줄로 코드·앱·웹을 만드는 **바이브 코딩이 업무 방식 자체를 바꾸는 중**.

- "‘점심 먹고 오는 동안 일 좀 해 놓을래?’ … 업무 방식 바꾼 바이브 코딩" (한국경제/네이버)
- "복잡한 코딩 몰라도 … 말 한마디로 세련된 홈피 만들죠" (매경/네이버)
- "코딩 몰라도 앱 만든다고? 바이브 코딩, 직접 해보니" (동아일보)

→ **생성 진입장벽은 사라졌다. "만드는 것"은 더 이상 차별점이 아니다.**

---

## 2. 결정적 한계 = 보안·안정성 (ReCoder의 표적)

바이브 코딩이 퍼질수록 **보안·안정성이 핵심 한계**로 드러나는 중.

- **"바이브코딩 벌써 옛말 … 보안 위험에 초고수 개발자 선호 흐름"** (연합뉴스) — 보안 위험이 역풍.
- **"바이브 코딩 확산, 보안 주의 필요 … 치명적 취약점 사례 확인"** (CIO Korea).
- **"바이브 코딩의 한계"** (요즘IT) — 흐름과 한계를 함께 정리.

여기에 앞서 모은 데이터가 같은 방향을 가리킨다:
- OWASP **Top 10:2025**에 *Software Supply Chain Failures* 신규 진입.
- KISA: 국내 SW 오픈소스 컴포넌트 **23만여 개 중 3.5% 취약, 0.49% 실제 악용 고위험** (뉴시스).
- Stack Overflow 2025: AI 불만 **66% "거의 맞지만 안 맞음"·45% 디버깅 시간↑**, **배포·모니터링엔 76%가 AI 사용 계획 없음**.

→ **핵심 메시지: "빨리 만들수록, 그걸 ‘안전하게 내보내는 일’이 더 어려워진다."**

---

## 3. 왜 DevOps가 아니라 보안인가 (포지셔닝 결정 근거)

- **DevOps 오케스트레이션**(빌드·배포·깃 연동·모니터링 연결)은 **MCP/에이전트로 표준화 가능 → 곧 커머디티.** 누구나 붙인다 = 해자가 안 된다.
- 반대로 **"AI가 만든 코드를 신뢰할 수 있게 만드는 일"(보안·배포 안정성)** 은 도메인 깊이·검증 로직이 필요 → 쉽게 복제 안 됨 = **해자**.
- 그래서 ReCoder는 **DevOps는 (필요하면) MCP로 흡수하고, 역량은 보안·배포 안정성에 집중**한다.

---

## 4. ReCoder의 보안·배포 안정성 (구현 vs 로드맵)

### 지금 구현·검증 🟢 — 데모에서 실제로 보여줄 강점
- **시크릿 스캐너** — AWS키/GitHub·Slack 토큰/private key/JWT 등을 **파일:라인까지 탐지, 값은 마스킹**. *바이브 코딩이 흔히 키를 코드에 박는 문제*를 직접 차단.
- **Context Gate 마스킹** — LLM에 보내기 전 비밀을 제거 → **생성 과정의 유출 차단**.
- **코드 적용 전 시크릿 경고** — 위험 코드를 그대로 적용하지 못하게.
- **게이트웨이 보안 모델** — 사용자에게 키 미노출 + **최소권한 IAM(Bedrock만)** + **per-user 토큰(폐기·7일 만료)** + **비용 캡**. *운영자 계정으로 다수에게 AI를 주면서도 보안·한도를 통제.*

### 로드맵 🔭 — 설계서 v10(코드 일부 존재), 발표는 "다음 단계"로
- 배포 전 스캔: **Trivy(이미지 취약점)·Hadolint·gitleaks** + **OPA 정책 게이트**.
- **Preflight(릴리스 계약 검증)** + **Approval Level(승인 단계)** + **RollbackPolicy(자동 복구)**.
- **Continuous Verification·IncidentMemory·Watchdog** — 운영 중 이상 대응.

> 발표 톤: "지금은 **시크릿 유출 차단 + 키 없는 안전한 AI 사용 + 배포까지** 를 실제로 동작시켜 보이고, 그 위에 **배포 전 취약점 스캔·승인·롤백**을 얹는 로드맵." (과장 없이, 🟢로 신뢰 확보 → 🔭로 비전 제시)

## 5. 경쟁 대비 차별화

| | 바이브 코딩 툴 (Copilot·Cursor·Lovable 등) | **ReCoder** |
|---|---|---|
| 역할 | 빠르게 생성 | 생성물을 **안전하게 검증·배포** |
| 보안 | 사용자 책임(키 박힘·취약점 그대로) | **시크릿 차단·마스킹·키 없는 사용·최소권한** 🟢 |
| 배포 안정성 | 사용자 책임 | (로드맵) **배포 전 스캔·승인·롤백** 🔭 |
| 관계 | 경쟁 | **그들의 출력을 안전하게 만드는 레이어**(보완) |

## 6. 발표용 핵심 문장

- "바이브 코딩으로 누구나 말 한마디로 앱을 만드는 시대가 됐다." (네이버·동아)
- "하지만 ‘바이브코딩 벌써 옛말’이라는 말이 나올 만큼, **보안 위험이 한계**로 떠올랐다." (연합뉴스)
- "**치명적 취약점 사례가 확인**되고, 국내 OSS 23만 개 중 3.5%에서 취약점이 나오는 시대 — 배포 전 검증과 비밀 점검은 옵션이 아니라 필수다." (CIO·KISA)
- "DevOps 연결은 MCP로 누구나 붙인다. **ReCoder의 해자는 ‘AI가 만든 코드를 안전하게 내보내는 것’ — 보안과 배포 안정성**이다."
- "ReCoder는 코드를 더 잘 만드는 도구가 아니라, **바이브 코딩의 결과물을 안전하게 배포·운영하는 보안 안전망**이다."

---

## 7. 정직한 경계 (발표 시)
- 🟢(시크릿 스캐너·마스킹·게이트웨이 보안·키 없는 사용)는 **지금 동작** → 데모로 신뢰 확보.
- 🔭(Trivy·Preflight·승인·롤백·Watchdog)는 **로드맵** → "비전으로 제시, 첫 줄기는 이미 동작" 구조로 말하면 과장이 아니다.
