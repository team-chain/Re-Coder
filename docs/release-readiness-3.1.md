## 1-1. 실제 Docker 엔진으로 돌린 검증 (2026-11-13)

이 환경은 Docker Hub가 막혀 공식 이미지를 받을 수 없어요. 그래서 **Docker 엔진·compose는 실제 것**을 쓰고, 베이스 이미지 4개(node·python·postgres·redis)는 이 환경에 설치된 같은 프로그램으로 **로컬에서 만든 대체 이미지**를 썼어요(Python은 3.13, 패키지 설치는 오프라인 캐시). 공식 이미지에서의 동작은 PC 검증(아래 3번 표 1·2)으로 확인해야 해요.

| 항목 | 결과 |
|---|---|
| 검증 하네스 (`verify-enterprise-live.py fixture`) | 정상판 13/13 통과, 결함판에서 원인 파일 지목, 개발 에이전트와 같은 경로(검증 복사본)도 13/13 통과 |
| 개발 에이전트 루프 전체 (가짜 AI + 실제 컨테이너) | 계약 → 생성 → 실제 컨테이너에서 "로그인 없이 열린 API" 검출 → 원인 파일만 교정 → 재검증 통과 (5/5) |
| 다중 서비스 배포 (스캐너는 대역) | 첫 배포 → 재배포 → 이미지 검사 차단(돌던 서비스 유지) → 기동 실패 자동 복구 → 승인 롤백, 그 사이 DB 데이터 유지, 공개 포트는 127.0.0.1만, 비밀값 파일 0600, 정리 후 남는 것 없음 (17/17) |
| 실패 분류 | 이미지를 못 받으면 "확인 불가"(코드 탓 아님), 빌드 실패·시작 실패·테이블 누락을 서비스·파일로 지목, 매번 컨테이너·볼륨·네트워크·이미지 누수 없음 (10/10) |
| 첫 배포 실패 · 포트 충돌 | 새로 만든 컨테이너를 내리고 데이터 볼륨은 유지, 포트 번호를 원인으로 안내 |

**실제 컨테이너에서만 드러난 결함 (모두 수정 · 회귀 시험 추가):**

1. **다중 서비스 생성 검증이 항상 실패하던 문제(치명적).** 검증 복사본을 만들 때 비밀값 가림이 compose의 `postgres://app:${X_PASSWORD}@db`를 `postgres://app:[MASKED]@db`로 바꿨어요. 서비스가 DB 인증에 실패해서, 실제 Docker에서는 PostgreSQL·MySQL·MongoDB를 쓰는 다중 서비스 생성이 전부 검증에 실패했을 거예요. 가짜 Docker 시험으로는 보이지 않았어요. 같은 가림이 JS 템플릿 문자열(`${pass}`)·파이썬 f-string(`{password}`)도 깨뜨려서 단일 앱 검증에도 영향이 있었어요. 이제 변수 참조는 가리지 않고 진짜 비밀번호 글자만 가려요.
2. **첫 배포가 실패하면 죽은 서비스가 계속 재시작하며 남던 문제.** 깨진 이미지가 다음 배포의 "직전 버전"으로 보관될 수도 있었어요. 이제 새로 만든 컨테이너와 이미지를 내리고 데이터 볼륨은 둬요.
3. **포트 충돌이 "시작 못 함"으로만 보이던 문제.** 이제 어느 포트를 다른 프로그램이 쓰는지 말해요.
4. **멀쩡한 서비스까지 고치라고 하던 문제.** 한 서비스가 죽으면 그것을 기다리던 서비스도 실패로 나와서, 교정이 원인이 아닌 코드까지 건드릴 수 있었어요. 이제 원인 서비스만 오류로 넘겨요.
5. **의존성 설치 실패를 시작 파일 탓으로 돌리던 문제.** 이제 실패한 빌드 단계를 보고 `requirements.txt`·`package.json`을 지목해요.
6. 검증 스크립트가 빌드 실패 로그를 보여 주지 않아 원인을 알 수 없었어요. 로그 끝부분을 결과에 실어요.
7. 단일 앱 승인 화면이 "다른 기기에서도 접속될 수 있다"고 안내했는데, 실제로는 2.0.32부터 이 PC에서만 열려요. 실제 동작대로 안내해요.

**이 방법으로도 확인하지 못한 것:** 공식 이미지(alpine·slim)에서의 빌드, MySQL·MongoDB·화면(nginx) 서비스, 실제 스캐너(Gitleaks·Hadolint·Trivy)를 거친 배포, 단일 앱 배포(스캐너가 없어 안전하게 차단됨까지만 확인).

## 2. 이번에 고친 것

- `first_run.py`: 진단 클래스 끝에 중복된 도달 불가 코드가 있었어요(정의되지 않은 변수 사용). 제거했어요.
- `tests/test_aws_client_defaults.py`: botocore 1.44부터 기본 재시도 모드가 바뀌면서 개발 환경에서만 실패했어요. 배포본(1.43.13 고정)은 정상이었어요. 버전과 관계없이 판정하도록 고쳤어요.
- 다중 서비스 공백 3개를 채웠어요.
  1. **서비스별 보안 게이트:** 배포 계획 단계에서 서비스마다 Dockerfile을 Hadolint로 검사하고, 실행 단계에서 Gitleaks와 서비스마다 Trivy로 검사해요.
  2. **로컬 compose 배포:** 승인 → 게이트 → 빌드 → 이미지 검사 → 기동 → 검증 → 기록 순서로 진행해요. 실패하면 자동으로 복구하고, 이력 화면에서 승인해서 롤백할 수 있어요.
  3. **명세 하네스:** 합격 조건 시험이 다중 서비스에서도 돌아요.
- **구조 분석 계약 대조:** 코드 맵에서 설계도와 실제 코드의 차이를 파일·줄로 보여 줘요. 위반은 교정 대상이고 배포 게이트가 막아요.
- **최종 검토에서 고친 것:**
  - 다중 서비스 배포가 공개 서비스 포트를 모든 네트워크에 열고 있었어요(같은 와이파이의 다른 기기에서 접속 가능). 단일 앱 배포와 같게 기본은 이 PC(127.0.0.1)에서만 열고, `RECODER_LOCAL_BIND=0.0.0.0`일 때만 넓혀요.
  - 같은 프로젝트에서 배포·롤백이 겹치면(버튼 두 번, 창 두 개) 이미지 태그와 기록이 꼬일 수 있었어요. 하나만 진행하고 나머지는 "이미 진행 중"으로 돌려보내요. 배포 기록 저장도 잠가서 동시에 끝나도 기록이 사라지지 않아요.
  - 계약 대조가 node_modules 안까지 훑고 심볼릭 링크를 따라갔어요. 무거운 폴더는 아예 들어가지 않고, 링크는 따라가지 않게(작업 폴더 밖 파일을 읽지 않게) 고쳤어요.
  - 다중 서비스 프로젝트에서 AWS(ECS·S3) 배포를 누르면 막는 장치가 없었어요. 배포 버튼 직후 점검과 ECS 시작 지점 두 곳에서 자원 생성 전에 멈추고, 검증한 compose·Dockerfile을 범용 초안으로 다시 만드는 것도 막았어요.
  - **패키지된 Core에 실제 다중 서비스 프로젝트를 주고 배포 화면 순서대로 호출해서 찾은 것(3건):**
    - 루트에 Dockerfile이 없다는 이유로, 지원하는 로컬 배포가 배포 버튼 직후 점검에서 막혔어요. 추천 대상도 막힌 ECS였어요. 다중 서비스 프로젝트는 로컬 Docker를 추천하고, 루트 기준 점검(Dockerfile·헬스 경로·이미지 검사 캐시)은 건너뛰어요. 서비스별 검사는 실행 게이트가 해요.
    - 승인 화면에 실제로 실행하지 않는 내용이 나왔어요(없는 이미지 `폴더:latest`, 포트 8080, 함께 띄울 DB와 그 접속값). 이제 실제로 실행하는 compose 내용(서비스·DB 목록, 열리는 주소, 비밀값 보관 위치, 롤백 대상)을 보여 줘요.
    - 포트를 다른 프로그램이 쓰고 있으면 첫 배포 승인 화면에서 미리 알려요.
- **Docker 자동 시작 2분 멈춤:** 패키지된 Core 점검에서 `/api/docker/ensure` 두 번째 호출이 120초 대기하는 걸 찾아 고쳤어요(회귀 시험 추가).

1~3번은 요금이 없어요. 4·6번은 요금이 들어요.

## 4. 남은 한계 (출시 문구에 반영)

- **AWS 다중 서비스:** AWS에 서비스 여러 개를 배포하는 기능과 묶음 단위 감시는 아직 없어요. 지금은 로컬에서만 돼요. 다중 서비스 프로젝트를 ECS·S3로 보내면 AWS 자원을 만들기 전에 이유를 알리고 멈춰요(예전에는 가드가 없어서 서비스 하나만 올라가거나 엉뚱한 빌드 오류로 끝날 수 있었어요).
- **계약 대조는 정적 분석:** 동적으로 만든 변수 이름·URL은 못 봐요. 실제 호출은 compose 통합 테스트로 확인해요.
- **실제 AI 성공률:** 실제 AI로 생성했을 때의 성공률은 측정 전이에요. 이 숫자가 나오기 전에는 "엔터프라이즈 앱을 완성한다"고 표현하지 않아요.
- **업무 로직:** 합격 조건으로 쓴 것만 시험해요. 화면 조건은 "확인 불가"로 남아요.
- **Gemini 라이브러리:** 패키지된 Core가 실행될 때 `google-generativeai` 지원 종료 경고를 출력해요. 지금은 동작하지만 후속 버전에서 새 라이브러리로 바꿔야 해요.
