# AI-DLC 데모 시나리오 — 결정 카드 → 코드 + 근거(ADR)

보드 카드 「AI-DLC 데모 시나리오 + ADR 산출물 정리」(DoD: 결정 카드→코드+근거 데모).
발표 10~12분 기준. 각 단계에 "말할 것"과 "보여줄 것"을 분리했다.

## 준비 (발표 전날)

- 데모 프로젝트: 빈 폴더에 `requirements.txt`(fastapi) + `main.py` 최소 앱.
- `.env` 의 PRIMARY 를 Sonnet 급으로 (설계 카드 품질 — `core/.env.example` 주석 근거).
- Docker Desktop 실행, AWS 프로필 연결 확인.
- 리허설 1회 — LLM 응답 시간이 데모의 유일한 변수다. 오래 걸리면
  "이 시간에 AI 가 설계 선택지를 만들고 있다"로 잇는다.

## 1막 — 문제 제기 (1분)

말할 것: "바이브 코딩의 문제는 코드가 아니라 **결정이 사라지는 것**이다.
왜 이 DB 인지, 왜 이 구조인지 아무도 모른 채 코드만 쌓인다. ReCoder 는
코드 전에 결정을 사람에게 보여주고, 그 결정을 근거 문서로 남긴다."

## 2막 — 결정 카드 (3분)

1. 채팅에 입력: **"게시판 기능 만들어줘. 글 작성/목록/삭제."**
2. 보여줄 것: 「설계 결정을 골라주세요」 모달 — 단계 배지(1/N), 선택지마다
   장단점.
3. 말할 것: "AI 가 임의로 정하지 않는다. 저장 방식·인증 여부 같은 구조적
   선택은 사람이 고른다. 형식이 깨져 제외된 결정도 숨기지 않고 사유를
   보여준다."
4. 저장 방식에서 **파일 기반**을 고른다 (데모 안정성).

## 3막 — 코드 + ADR (3분)

1. 「이 선택으로 생성 →」 → 생성된 디프 승인 → 적용.
2. 보여줄 것: `docs/adr/` 에 생긴 ADR 파일 — 방금 고른 결정과 근거가 그대로.
3. 말할 것: "이 문서가 산출물이다. 한 달 뒤 '왜 파일 저장이지?' 에 대한
   답이 코드 옆에 남는다. 같은 결정이 반복되면 ADR 은 중복 생성되지 않는다."

## 4막 — 검사와 배포 게이트 (3분)

1. Ship 화면에서 보안 스캔 — **Docker 를 끈 상태로 먼저 시연**:
   "확인하지 못했습니다" 경고. 말할 것: "검사를 안 한 것은 통과가 아니다.
   이 상태로 배포하려면 이중 확인을 요구하고, 실행 직전에 빌드된 이미지로
   스캔을 한 번 더 돈다."
2. Docker 켜고 재검사 → 통과 → S3 배포 실행 → **진행률이 실시간으로**
   차오르는 것을 보여준다 → 배포 URL 접속.

## 5막 — 감시와 롤백 (2분, 시간 없으면 화면 캡처로 대체)

1. v2 를 일부러 깨뜨려 재배포 → 롤백 **제안** 카드.
2. 말할 것: "감시가 이상을 발견해도 멋대로 되돌리지 않는다 — 제안하고,
   사람이 승인해야 이전 버전으로 간다." → 승인 → 복귀 확인.

## 마무리 (30초)

"ReCoder 의 원칙은 하나다 — **AI 가 만들되, 결정과 실패를 숨기지 않는다.**
결정은 카드와 ADR 로, 실패는 미검증·차단 사유로 화면에 남는다."

## 질문 대비

- "AI 가 다 하는 것과 뭐가 다른가?" → 결정 카드·ADR·승인 게이트, 즉 사람이
  개입하는 지점을 구조로 만들었다.
- "품질이 낮은 스택이면?" → 검증 품질이 낮다고 화면에 표시한다. 숨기는 것보다
  아는 것이 낫다.
- "보안은?" → 스캔 미실행=미검증 원칙, OPA 정책 게이트, 최소권한 IAM 셋업.
