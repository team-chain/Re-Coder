# ReCoder — 포지셔닝 & 서비스 필요성 (근거 종합)

> 구현된 실제 코드 + 구현 설계서 + 수집한 국내외 출처를 하나로 묶은 **발표·기획용 근거 정리**.
> 표기: 🟢 현재 구현·검증됨 / 🔭 설계서상 비전(확장 예정).

---

## 1. 한 줄 포지셔닝

> **"ReCoder는 AI 코딩툴이 아니라, AI가 만든 변경을 검증·배포·운영까지 안전하게 잇는 AI Ops Agent다."**

3축으로 보면:
- **Code 생성이 아니라 Change 통제** — "코드를 써준다"가 아니라 "AI가 만든 변경을 안전하게 반영한다".
- **AI 편집기가 아니라 배포 안전망** — 생성 다음 단계(검증·배포·운영)를 책임진다.
- **개발 보조가 아니라 운영 가능한 AI DevOps** — 개발→배포→운영을 한 흐름으로.

그리고 지금 **실제로 구현된 1학기 MVP**가 이 포지셔닝을 작은 규모로 증명한다:
> **"자연어 한 줄 → 동작하는 결과물 → 인터넷 공개 URL을, 사용자는 키 없이 / 운영자가 정한 한도·보안 안에서."** 🟢

---

## 2. 시장 맥락 — "왜 지금인가"

AI 코딩은 **이미 메인스트림**이다. ReCoder는 "AI 코딩이 뜰까?"를 증명할 필요가 없고, **이미 커진 시장의 다음 병목**을 노린다.

- **Stack Overflow 2025**: 응답자 **84%**가 AI 도구 사용 중/예정, 전문 개발자 **51%**는 매일 사용. ChatGPT 82%·Copilot 68%가 대표 진입 제품.
- **ZDNet Korea**: "개발자 **95%**가 AI를 사용"한다는 보도.
- **State of FE/JS Korea 2025**(국내): 코드 어시스트 35.48%·리팩토링 22.29%로 활발, **61.13%**가 "개발 업무에 큰 영향".

→ **결론**: 진입점(코드 생성)은 이미 Copilot/Cursor류가 장악. ReCoder의 시장은 "생성 다음" = **안전한 검증·배포·운영**.

---

## 3. 핵심 문제(=시장의 공백) 3가지

각 공백마다 **근거(출처)** + **ReCoder의 대응(구현/비전)** 을 짝지었다.

### 3.1 신뢰·품질 공백 — "생성은 쉬워졌는데 결과를 못 믿는다"
**근거**
- SO 2025: **46%**가 AI 정확성 불신. AI 불만 1위 **66%** "거의 맞지만 완전히 맞지는 않음", **45%** "AI 코드 디버깅에 시간 더 듦".
- ITWorld(2025 Go 설문): **53%** "제대로 작동하지 않는 코드", **30%** "실행은 되나 저품질".
- 한국저작권위(KCC) 이슈브리프: AI 코드 생성이 **기술 부채 가속·코드 품질 저하** 우려.

**ReCoder 대응**
- 🟢 에러 **자동 감지·수정** 제안, 코드 적용 전 **diff·시크릿 경고**, 생성물 검증 흐름.
- 🔭 Preflight / RemediationProposal / Continuous Verification(설계서) — "AI 변경을 바로 실행하지 말고 검증·승인·복구".

### 3.2 배포·운영 공백 — "실패 비용 큰 단계에서 AI를 못 믿는다"
**근거**
- SO 2025: **Deployment & monitoring**에 대해 **76%**가 "AI 사용 계획 없음" — 고책임 영역일수록 AI 불신.
- 토큰포스트: AI 도구가 리뷰·문서엔 도움되나 **배포 속도 −1.5%, 안정성 −7.2%** 가능 → "생성은 쉬워졌지만 관측·검증은 더 어려워졌다".
- AWS 한국어 기술블로그: **알림 설정 미흡·모니터링 활용 부족·대응 지연**.
- DORA 2025: AI는 조직의 강점·약점을 **증폭** — 성과는 플랫폼·워크플로·정책 같은 **기반**에 달림.

**ReCoder 대응**
- 🟢 **개발→배포(S3) 한 흐름** + 진행 상황 가시화(디스코드 진행 임베드), **키 없이** 배포까지.
- 🔭 Watchdog / IncidentMemory / Discord ChatOps 대응 / RollbackPolicy(설계서) — 운영 중 이상 대응·복구.

### 3.3 보안·공급망 공백 — "빨리 만들수록 리스크가 따라온다"
**근거**
- **OWASP Top 10:2025**: "Software Supply Chain Failures"가 신규 항목으로 진입 → 공급망이 보안 우선순위로 격상.
- KISA(뉴시스 보도): 국내 SW 제품 오픈소스 컴포넌트 **약 23만 1천 개 중 3.5%에서 취약점**, **0.49%는 실제 공격에 악용된 고위험**.
- 보안뉴스·드림시큐리티: **2025 핵심 위협 = SW 공급망 공격**.
- ZDNet Korea: AI가 **취약 코드·잘못된 의존성·라이선스 문제**를 키울 수 있음.

**ReCoder 대응**
- 🟢 **시크릿 스캐너**(AWS키·토큰·private key 등 파일:라인 탐지, 값 마스킹) + **Context Gate 마스킹**(LLM 전송 전 비밀 제거) + **최소권한 IAM·키 미노출 게이트웨이**.
- 🔭 Trivy/Hadolint/gitleaks + 승인 레벨(Approval) + 배포 전 차단(설계서).

## 4. 경쟁 대비 차별화

| | Copilot / Cursor / Cline | **ReCoder** |
|---|---|---|
| 핵심 | 코드 생성·편집(진입점 장악: ChatGPT 82%·Copilot 68%) | **생성 다음** — 검증·배포·운영·보안을 잇는 실행 안전망 |
| 배포·운영 | 사용자 몫 | **한 흐름에 포함**(개발→공개 URL) 🟢 |
| 사용 모델 | 개인 키/구독 | **키 없이** 팀·교실 단위(게이트웨이가 운영자 계정 대행, per-user 한도) 🟢 |
| 증명 | — | **디스코드 한 줄 → 공개 URL 라이브 데모** 🟢 |

→ "누가 더 코드를 잘 쓰나"로 정면 충돌하지 않는다. **"누가 더 안전하게 배포·운영까지 잇나"** 로 차별화.

## 5. 타깃 시장

- **1차**: 주니어 개발자 / 소규모 팀 / 교육(부트캠프·수업). "확장 설치 + 한 줄"로 끝나는 무설정 경험이 강점.
- **대리 지표**(국내): 2024 클라우드 산업 인력 **33,217명**, 그중 **클라우드 개발자 11,146명**(가장 큰 비중) — 배포·운영까지 만지는 개발자층의 국내 하위시장.
- **확장(SaaS)**: 게이트웨이가 이미 **per-user 쿼터 + 풀 비용 캡**을 강제 → 구독/티어 과금의 기술 백본을 보유. 🟢

## 6. 발표용 핵심 문장 (그대로 인용)

- "개발자의 **84%**가 AI 도구를 사용하거나 사용할 계획이며, AI 코딩 시장은 이미 대세가 됐다." (SO 2025)
- "하지만 **배포·모니터링처럼 실패 비용이 큰 영역은 76%가 AI 활용 계획이 없다** — 개발자는 운영 단계에서 AI를 아직 신뢰하지 못한다." (SO 2025)
- "AI 불만 1위는 **‘거의 맞지만 완전히 맞지 않는 답’(66%)** 과 **디버깅 시간 증가(45%)** — 생성 이후의 검증·운영 안정성이 핵심 병목." (SO 2025)
- "국내 SW 오픈소스 컴포넌트 **23만여 개 중 3.5%에서 취약점, 0.49%는 실제 악용** — 배포 전 보안 점검은 옵션이 아니라 필수." (KISA/뉴시스)
- "따라서 ReCoder는 단순 AI 코딩 도구가 아니라, **개발–배포–운영을 안전하게 잇는 AI Ops Agent**다."

---

## 7. 정직한 경계 (발표 시 과장 방지)

- 위 ReCoder 대응 중 🟢 는 **현재 구현·검증**(코드 에이전트·에러분석·시크릿 스캐너·게이트웨이·S3 배포·디스코드 패널), 🔭 는 **설계서상 비전**(Trivy/Watchdog/Preflict/IncidentMemory 등 — 코드 일부 존재하나 데모 핵심 경로 밖).
- 즉 발표 논리는 **"비전(AI Ops)을 제시하고, 그 첫 줄기(개발→안전 배포, 키 없이)를 실제로 동작시켜 보인다"** 가 가장 정직하고 설득력 있다.
