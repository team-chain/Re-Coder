# 코드 생성 결과의 삭제 후보 경고 (A4)

`/api/code/generate`가 생성한 전체 파일 내용과 **생성 완료 시점의 저장된 파일**을 비교해 각 op에 `removal_check`를 붙인다. 모델이 반환한 경고나 `create`/`edit` 표시는 신뢰하지 않고 실제 적용 경로를 읽는다. 추가 LLM 호출, 파일 쓰기, AWS 배포는 수행하지 않는다.

CodeAgent는 `모두 적용` 위에 파일 전체 합계를, 각 파일 카드에 함수명·HTTP 메서드/경로·기존 줄 번호를 표시한다. 함수와 라우트는 따로 센다. 하나의 Python 핸들러를 삭제하면 함수 1개와 라우트 1개가 함께 표시될 수 있다. 모든 카드에서 `변경 보기`를 열 수 있다. 경고는 검토를 돕는 정보이며 기존 적용 승인 동작을 차단하지 않는다.

## 응답

```json
{
  "removal_check": {
    "status": "checked",
    "removed": [
      { "kind": "function", "name": "listTodos", "line": 3 },
      { "kind": "route", "name": "GET /todos", "line": 6 }
    ]
  }
}
```

- `checked`: 지원하는 정적 선언을 비교했다. 전체 기능이 안전하다는 뜻은 아니다.
- `new_file`: 비교할 저장 파일이 없다.
- `unavailable`: 미지원 형식, 읽기/구문 오류, 1 MB 초과 등으로 비교하지 못했다. 화면에 이유를 표시한다. 구버전 Core가 필드를 보내지 않아도 검사 미완료로 표시한다.

## 범위와 한계

- Python: AST로 이름 있는 함수·async 함수·메서드·중첩 함수의 범위를 구분한다. FastAPI/Flask 방식의 HTTP 메서드 데코레이터, `route`/`api_route`의 문자열 경로와 정적 `methods` 목록을 비교한다.
- JavaScript/TypeScript(JSX/TSX 포함): 일반 이름 있는 `function` 선언, 변수에 할당된 함수/화살표 함수, `app`/`router`/`server`/`api` 및 `*Router`의 문자열 경로 등록을 정적으로 찾는다. `router.route('/path').get(...).post(...)`도 지원한다. 주석·문자열·일반 정규식 리터럴을 제외하고 괄호가 잘린 소스는 검사 미완료로 처리한다. 완전한 JS/TS 구문 분석기는 아니다.
- 동적 경로·라우터 별칭/마운트 접두사·객체/클래스의 JS 메서드·프레임워크 파일 기반 라우팅 등은 모두 추적하지 않는다. JS 함수는 이름과 개수를 비교하며 Python처럼 범위를 구분하지 않는다. 특수 정규식/템플릿/JSX 문법에서는 누락 또는 검사 미완료가 발생할 수 있다.
- 같은 이름의 구현 변경은 삭제로 보지 않는다. 이름 변경·파일 이동은 삭제 후보가 될 수 있으므로 diff로 판단한다.
- 비교 기준은 diff 왼쪽에 쓰이는 저장 파일이다. 저장하지 않은 편집, 생성 후 파일 변경, 이전 제안의 적용 여부는 반영하지 않는다. 적용 전에 저장 상태와 diff를 확인한다.
- 요청별 프로젝트 루트와 대상 폴더를 사용한다. 워크스페이스 밖을 가리키는 심볼릭 링크는 읽지 않는다. 경로 정규화는 기존 확장의 적용 규칙과 맞춘다.

## 수동 검증

ECS는 꺼둔다. 별도 `a4-warning-test.js` 파일에 `listTodos`, `createTodo` 함수와 `GET /health`, `GET /todos`, `POST /todos`를 저장한다.

1. 해당 파일의 `/health`만 남기고 두 함수와 `/todos` GET/POST를 삭제하라는 코드 생성 요청을 보낸다.
2. 설계 선택 후 생성된 파일 카드와 전체 요약에서 **함수 2개 · 라우트 2개** 및 네 항목의 이름을 확인한다. 아직 적용하지 않는다.
3. `변경 보기`에서 실제 삭제 부분과 경고를 대조하고, 원본 파일이 그대로인지 확인한다.
4. 원본 기준으로 `/health` 응답의 버전 문자열만 바꾸고 나머지는 모두 유지하라는 새 요청을 보낸다. 생성 diff가 실제로 나머지를 보존하면 삭제 후보 경고가 없어야 한다.

LLM이 요청과 다르게 생성하면 먼저 생성 diff를 확인한다. 경고의 정답은 요청 문장이 아니라 실제 생성된 전체 파일과 저장 원본의 차이다. 자동 테스트는 고정된 생성 응답으로 이 차이를 검증한다.
