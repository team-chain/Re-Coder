## 구현한 동작

1. **검사 범위와 근거 계약**: 경로 탐색, SQL, 인증, 권한, 입력 처리의 실행/차단/미실행을 구조화한다. 일반 문자나 빈 검색어만 보낸 결과를 SQL 검사 완료로 세지 않는다. URL 및 POST 본문, 정상·변형·대조 요청을 남기도록 지시한다.
2. **후보 검증**: 발견 항목은 같은 경로·메서드의 서로 다른 검사/대조 요청과 응답이 있어야 한다. 요청이 해당 검사 기록에 없거나 대상 경로 밖이면 후보에서 제외한다. 같은 요청 쌍의 중복은 합친다. 제외된 원문은 원본 기록에 남는다.
3. **CVSS 계산**: CVSS 3.1 기본 벡터를 코드로 계산한다. 이전 AWS 기록의 `AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N`은 9.1이 아니라 **7.5**다. 잘못된 벡터는 점수를 표시하지 않는다. 계산의 정확성과 모델이 선택한 영향 지표의 타당성은 별개다.
4. **진행 시각화**: 환경 준비 → 작업 시작 → PentAGI 진단 → 결과 정리 → 환경 정리. 실제 작업 상태와 개수만 사용하며, 실행 중 작업만 움직인다. 최대 6개 카드를 먼저 보여 주고 나머지는 펼쳐 본다. 새 실행 시 진행 화면으로 이동하며, 키보드·작은 화면·동작 줄이기를 지원한다.
5. **연결 복구**: 상태 조회만 3/6/12초 간격으로 최대 3회 자동 재시도한다. 시작·승인·중단은 자동 재전송하지 않는다. 상태 요청은 화면에서 45초 감시하며, 실패 중에는 마지막 기록을 표시하고 애니메이션을 멈춘다. 이후에는 상태 확인 버튼을 사용할 수 있다.
6. **보고서**: 로컬 저장 보고서는 대상·시각·공급자·종료 상태, 검사 범위, 요청/응답, 대조 근거, 계산된 점수, 수정 제안을 Markdown으로 연다. 원본 JSON도 별도로 열 수 있다. 과거의 비구조화 보고서를 안전 판정으로 승격하지 않는다. AWS 보고서는 수신할 때 다시 검증한다.
7. **종료 호환성**: 별도 PentAGI 서버가 최종 작업 성공 뒤 flow를 `waiting`으로 남기는 경우에도 실행 완료를 인식한다. 상세 보고서 수신 실패 시 마지막 작업 결과를 계속 보여 준다. 기존 로컬/AWS 정리 절차는 유지했다.

## 아직 출시 승인으로 주장할 수 없는 것

- 구조화된 응답도 AI가 작성한다. UI의 항목은 **근거가 첨부된 후보**이며 독립적으로 확정한 취약점이 아니다.
- 이번 어댑터에 승인된 테스트 신원/접근 정책 전달 계약이 없으므로 인증·권한을 검사했다고 모델이 주장해도 미검증으로 남긴다. 실제 인증·권한 테스트 완료를 광고할 수 없다.
- 로컬/별도 서버 경로의 대상 제한은 기존과 같이 URL 검증과 지시문이다. 승인 대상만 허용하는 네트워크 강제 격리를 새로 구현하거나 검증한 것이 아니다. 기존 AWS 격리 경로도 이번 세션에서 실 AWS로 재시험하지 않았다.
- 로컬 SQL 미탐이 실모델에서도 해결됐는지, 임의 프로젝트·모든 모델의 탐지율·오탐률은 아직 확인하지 못했다. 이전 미통과 기록 `security-live-followup-20261110.txt`는 유효하며 덮어쓰지 않았다.
- Haiku 코드 감사 정확도, 다중 서비스 생성/검증, 운영 부하·비용·GitHub 알림은 이번 변경의 합격 항목이 아니다.
- 따라서 이 브랜치는 **기능 보강과 로컬 회귀를 마친 출시 후보**다. 실모델 인수, 격리 요구사항, 번들 Core/VSIX 설치 검증 전에는 출시 완료라고 표시하지 않는다.

## 사용자가 기존 연결로 실모델 인수하는 방법

1. 이 브랜치의 `extension`에서 `npm ci`, `npm run build` 후 기존 개발 호스트 실행 방법으로 ReCoder를 연다. 기존 SecretStorage·AWS 연결을 그대로 사용한다. 개발 체크아웃 전용 절차이며, 사용자에게 Node 설치를 새로 요구하는 제품 기능이 아니다.
2. 개발 검증용 PC의 Node 22.13 이상에서 다음 테스트 앱을 실행한다. 실제 데이터나 외부 DB는 사용하지 않는다. 앱은 localhost에만 바인딩하고 읽기 요청만 받는다. 파일명은 매 검사 새 것으로 지정한다.

   ```powershell
   node harness/redteam-sql-fixture.js serve --port 19371 --out ../.test-artifacts/gpt-sql-01.jsonl
   ```

3. Security → 레드팀 테스트 → 내 PC의 테스트 앱 → 시작. 대상은 `http://localhost:19371/`이다. 기존 공급자를 고르고 정상 승인 창에서 범위·모델 비용을 확인한다. 하네스가 AI를 직접 호출하거나 비용 승인을 생략하지 않는다.
4. 완료 후 원본 기록의 **원본 JSON 열기**에서 보고서를 별도 파일로 저장한다. 예를 들어 `../.test-artifacts/gpt-report-01.json`.
5. 실제 HTTP 기록과 보고서를 대조한다.

   ```powershell
   node harness/redteam-sql-fixture.js verify --report ../.test-artifacts/gpt-report-01.json --journal ../.test-artifacts/gpt-sql-01.jsonl
   ```

   종료 코드 0은 이 합성 SQL 사례의 기준을 만족했다는 뜻이다. `/search`의 실제 응답에 나타난 무작위 합성 표식, 같은 경로의 대조 응답, `/safe`의 음성 대조, 실행 완료·환경 정리를 요구한다. 모델이 근거를 지어내거나 표식을 놓치거나 정리를 실패하면 종료 코드 1이다. 이 한 사례의 합격을 앱 전체의 보안 통과로 표시하면 안 된다.
6. GPT·Claude 각각 새 앱 실행과 새 기록으로 반복하고, 모델 ID·실행 시간·원본 결과·실제 요청 기록을 함께 보관한다. 앱은 Ctrl+C로 종료한다. PentAGI 검사 중단은 ReCoder의 중단·환경 삭제를 사용한다.
