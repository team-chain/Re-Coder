# ReCoder 1.1.10 — GitHub 첫 커밋·저장소 변경 및 배포 진행 표시

## 수정

- 첫 커밋 전에 스테이징했다가 삭제한 파일(`AD`)은 `git add -A` 이후 인덱스에서 사라집니다. 이를 다시 `commit --only`에 넘겨 `pathspec` 오류가 발생했습니다. 스테이징 후 인덱스 또는 HEAD에 실제로 존재하는 경로만 커밋에 넘깁니다. 기존에 커밋한 파일의 삭제와 선택하지 않은 스테이징 파일은 보존합니다. 추가 취소만 있으면 정리 사실을 알리고 빈 커밋을 만들지 않습니다.
- 연결된 프로젝트에도 저장소 변경·새 비공개 저장소 생성 메뉴를 제공합니다. 현재 연결 대상 확인과 명시적인 변경 요청 후 origin을 변경합니다. 로컬 커밋과 기존 GitHub 저장소는 보존하며, 업로드는 별도의 푸시 승인으로 실행합니다. 진행 중인 연결·커밋·푸시는 같은 패널에서 겹쳐 실행하지 않습니다.
- Docker 승인 실행에 `/api/deploy/execute/stream`을 추가했습니다. 기존 실행 함수의 잠금·보안 검사·컨테이너 교체·헬스 확인·롤백 처리를 그대로 사용하며 실제 단계가 바뀔 때 SSE를 보냅니다. 화면 연결이 끊겨도 승인된 배포는 계속되고, 클라이언트가 같은 배포를 자동으로 재실행하지 않습니다.
- Docker 패널에 준비 → 이미지 빌드 → 보안 확인 → 컨테이너 시작 → 헬스 확인 → 결과 저장을 표시합니다. 헬스 확인 대기는 완료로 표시하지 않습니다.
- 기존 S3 SSE를 캔버스의 진행 카드에 연결했습니다. 단계와 업로드 파일 수·파일명을 표시하며, 업로드 비율만 실제 파일 수를 기준으로 계산합니다.

## 검증

- 확장 테스트 **403개 통과**, 기존 2개 건너뜀. 최초 커밋의 추가 취소, 선택하지 않은 파일 보존, 실제 로컬 bare 저장소 푸시, origin 변경, 비공개 저장소 생성 요청, SSE 청크·UTF-8·CRLF·연결 종료·인증 재시도를 포함합니다.
- Core 테스트 **194개 통과**, 1개 건너뜀. Docker/S3 배포·SSE·헬스 판정·GitHub·세션 인증·배포 회귀를 포함합니다.
- 실제 사용자 프로젝트 복사본을 별도 `recoder-qa-1110` 컨테이너 / 18120 포트로 빌드·검사·실행했습니다. hadolint/gitleaks 발견 항목 0개, 빌드 후 이미지 검사 통과, HTTP 헬스 및 HTML/JS/CSS 응답 정상. 내부 문서·시크릿·없는 경로는 404입니다.
- 실제 Docker SSE 관측: 0초 준비·빌드 → 3.81초 이미지 검사 → 5.33초 컨테이너 시작 → 7.42초 헬스 확인 → 7.84초 결과 저장 → 8.45초 완료.
- TypeScript 호스트·웹뷰 검사 통과.
- 실제 배포 번들과 SidebarProvider를 사용한 격리 브라우저 검증: 연결 후 저장소 변경 메뉴, 새 비공개 저장소 연결 요청, `AD package.json`을 포함한 최초 커밋 및 푸시 승인 완료. Git 작업은 임시 프로젝트에서 실행했고 GitHub API는 테스트 응답을 사용했습니다.
- 로컬 HTTP SSE를 실제 ApiClient로 수신한 화면 검증: S3 `파일 업로드 1/2 · 50%`와 파일명 표시 후 완료, Docker 승인 후 진행 카드와 최종 헬스 통과 결과 표시. 이 화면 검증은 외부 AWS·Docker 실행을 대체 응답으로 격리했습니다.
- VSIX를 풀어 새 사용자 프로필·Python이 없는 PATH에서 내장 Core 1.1.10 시작, 세션 인증, 프로젝트 분석, 배포 계획·취소, 새 SSE 엔드포인트, 재시작·종료 검증 통과.
- VSIX 내부 호스트·웹뷰·Core가 검증한 산출물과 바이트 단위로 일치합니다. SHA256: `e022cc16f0d7c511e60902ac67dc7a0b285af718231c69f046dd2d66342e5907`.

사용자 원본 프로젝트에서 커밋하거나 원격 GitHub 저장소를 생성·변경·푸시하지 않았습니다. AWS S3 업로드도 이번 검증에서는 실행하지 않았습니다. 외부 서비스 동작은 기존 계약 검사와 격리된 응답으로 확인하고, 실제 Docker 배포는 복사본에서 실행했습니다.

설치 파일: `extension/dist/recoder-1.1.10-win32-x64.vsix`. 설치 완료 후 CLI에서 `recoder-team.recoder@1.1.10`을 확인했습니다. VS Code의 `Developer: Reload Window`로 적용합니다. 검증용 브라우저 탭·서버·Docker 컨테이너는 정리했습니다.
