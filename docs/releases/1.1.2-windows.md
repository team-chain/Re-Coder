# ReCoder 1.1.2 — Windows 실행 및 배포 점검

## 설치해서 실행

1. F5 개발 창을 실행 중이라면 먼저 Shift+F5로 종료합니다.
2. 일반 VS Code 창에서 Ctrl+Shift+P → `Extensions: Install from VSIX...`를 실행합니다.
3. `extension/dist/recoder-1.1.2-win32-x64.vsix`를 선택합니다.
4. Ctrl+Shift+P → `Developer: Reload Window` → `ReCoder: Restart Core`를 실행합니다.
5. 프로젝트 전체 폴더를 엽니다. 영상의 프로젝트는 `C:\Users\dy981\OneDrive\바탕 화면\test temp`입니다. `src`만 열면 package.json과 Dockerfile을 찾지 못합니다.
6. Ctrl+Shift+P → `ReCoder: Open Workspace` → Deploy로 이동합니다.

설치본은 Core 실행 파일을 포함합니다. 별도 Python 서버 실행은 필요하지 않습니다. AI 작업에는 기존 AI 연결 설정이 필요하며, Docker 배포에는 Docker Desktop, AWS 배포에는 사용자 AWS 연결이 필요합니다.

## 로컬 Docker 배포

프로젝트를 Docker 노드에 끌어 놓고 Dockerfile·이미지·포트·검사 결과를 확인한 뒤 배포를 승인합니다. 영상의 React 프로젝트는 컨테이너 포트 3000을 사용합니다. 다른 프로그램이 호스트 포트를 사용 중이면 비어 있는 호스트 포트를 선택합니다.

배포 후 HTTP 헬스 체크와 화면 접속을 모두 확인합니다. 컨테이너 실행만 성공하고 헬스 체크가 실패한 경우에는 정상 서비스로 표시하지 않습니다. 이력에서 이전 정상 이미지로 롤백할 수 있습니다.

React/Vite의 S3 배포는 프로젝트 루트에서 `npm run build`를 실행한 다음 `build` 또는 `dist` 폴더를 선택합니다. 빌드 전 CRA/Vite 진입 파일을 올리려 하면 중단하고 필요한 동작을 안내합니다.

## 포함한 수정

- GitHub 로그인·저장소 연결·첫 커밋·승인 후 푸시, Discord 노드 표시·연결·재시도 등 1.1.1 수정 포함.
- 한쪽 포트만 지정해도 지정값을 보존. 환경변수·프로젝트 정보·감시 설정을 실행과 이력에 유지.
- 한국어·특수문자 프로젝트의 유효한 Docker 이름 생성.
- Dockerfile 최종 스테이지의 TCP 포트 감지. 실제 Next.js/서버 헬스 경로 탐지 및 명시적 설정 보존.
- 빌드 후 이미지 재검사와 검사한 이미지 ID 실행. 검사 차단 후 재시도 우회 방지.
- 빈/손상된 Trivy·Gitleaks 보고서와 Hadolint 실행 실패를 통과로 처리하지 않음.
- 생성된 React 정적 컨테이너용 ECS wget 헬스 체크. 해당 런타임의 포트 불일치는 AWS 변경 전에 차단.
- React 정적 Dockerfile 저장 승인에 .dockerignore 생성을 안내하고 함께 생성. 기존 파일 보존.
- Windows Docker 출력 UTF-8 처리와 긴 빌드·스캔 응답 대기 개선.

## 검증 범위

검증 결과는 같은 폴더의 `1.1.2-verification.md`에 기록합니다. 실제 AWS 배포, 사용자 GitHub 원격 푸시 및 Discord 채널 메시지 전송은 자동 검증과 구분합니다. 유료 리소스 생성이나 사용자 채널 전송은 이번 검증에서 실행하지 않습니다.
