# ReCoder 1.1.0 — Windows x64 설치와 사용자 검증

설치 파일: `extension/dist/recoder-1.1.0-win32-x64.vsix`.
Python 런타임과 Core가 포함돼 있으며 Python 서버를 직접 띄우거나 npm 빌드를 할 필요가 없다.

## 설치

1. 기존 **Extension Development Host** 창을 닫는다.
2. 일반 VS Code에서 확장 화면(`Ctrl+Shift+X`)의 `…` → **Install from VSIX…**를 선택한다.
3. 위 `1.1.0-win32-x64.vsix`를 설치하고 VS Code 창을 다시 로드한다.
4. 테스트할 프로젝트 폴더를 연 뒤 `ReCoder: Open Workspace`를 실행한다.
5. 기존 개발 Core와 경로가 다르다는 안내가 나오면 `ReCoder: Restart Core`를 실행한다.

처음 실행할 때 Core의 압축 해제에 시간이 걸릴 수 있다. 확장이 최대 60초까지 기다린다.
VS Code 확장 상세 화면에서 버전이 **1.1.0**인지 확인한다.

## 연결

- AWS: 상단 AWS 연결에서 본인의 프로필 또는 브라우저/IAM 연결 절차를 진행한다.
  기존 키 등록 경로도 유지한다. 배포 리소스와 요금은 연결한 사용자 AWS 계정에 귀속된다.
- AI: 본인 AWS Bedrock 권한을 사용하거나, 제공받은 게이트웨이 등록 코드가 있다면
  명령 팔레트의 `ReCoder: Connect to Gateway (Enroll)`로 연결한다.
- 로컬 Docker 및 컨테이너 배포: Docker Desktop을 실행한다.
- GitHub 연동: Git 설치와 GitHub 로그인을 확인한다.

Core 동봉은 사용자 인증을 대신하지 않는다. 개발자의 키·`.env`·등록 토큰은 배포본에 없다.

## 확인할 흐름

| 확인 | 기대 동작 |
| --- | --- |
| 첫 화면 | 간결한 Develop·Deploy·Security 메뉴, 필요할 때 AWS/AI 패널 열기 |
| 프로젝트 클릭 | 소스 파일과 import 관계 표시 → 파일 클릭 시 함수 관계 표시 |
| Develop | 요청 전송 → 제안/설계 선택 → 승인 → 코드 결과 → 적용과 ADR 기록 |
| Deploy | Three.js 캔버스에서 프로젝트 드래그 → 대상 설정 → 승인 카드 |
| AWS 미연결 | AWS 대상 잠금, 연결 안내; 배포 실행 안 됨 |
| 승인 취소 | 파일/리소스 변경 없음 |
| 승인 후 실행 | 보안 게이트 상태 → 배포 결과와 실제 리소스 이름 |
| 배포 실패/롤백 | 실패 원인과 이전 배포 이력 확인, 승인 후 롤백 |
| Security | 검사 중 화면을 이동해도 결과 유지, 미검증은 통과로 표시하지 않음 |
| 재실행 | VS Code 재시작 후 Core 자동 기동, 저장한 연결 설정 유지 |

이 목록의 실제 AWS·AI 결과는 사용자의 계정 권한, 모델 이용 가능 여부, Docker 상태에 따라 확인한다.
기존 IAM 역할에서 새 캔버스 조회 권한이 부족하면 화면의 권한 안내에 따라 정책을 갱신한다.

## 문제가 생겼을 때

오류 화면과 발생 단계를 기록하고 `ReCoder: Run Diagnostics`를 실행한다.
Core 기동 오류는 `%USERPROFILE%\.recoder\core.log`에서 확인할 수 있다.
`runtime.json`에는 세션 인증 토큰이 있으므로 파일 전체를 공유하지 않는다.

파일 무결성 확인:

```powershell
Get-FileHash -Algorithm SHA256 'extension/dist/recoder-1.1.0-win32-x64.vsix'
Get-Content 'extension/dist/recoder-1.1.0-win32-x64.vsix.sha256'
```
