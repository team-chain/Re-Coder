# ReCoder 1.1.5 — 코드 화면 안에서 대화·설계·적용

## 사용

업데이트 설치 후 VS Code에서 **Developer: Reload Window**를 실행합니다.
ReCoder → **Develop → 코드 생성·수정 → AI와 대화하기**에서 요청을 입력합니다.

1. 대상 폴더와 참고 파일을 선택하고 요청을 보냅니다. Ctrl+Enter도 사용할 수 있습니다.
2. 설계 선택이 표시되면 원하는 옵션을 고르고 **이 선택으로 생성**을 누릅니다.
3. 생성된 파일과 설계 기록(ADR)의 **변경 보기**를 확인합니다.
4. **적용** 또는 **모두 적용**을 눌러 파일을 저장합니다.
5. 같은 입력창에서 다음 수정 요청을 이어갑니다.

오른쪽 AI 패널과 상단 대화 토글은 제거했습니다. 개발 입력과 결과는 중앙 코드 화면에 함께 있으며, 탭 이동 후에도 유지됩니다. 연결 상태 확인은 기능을 누르기 전부터 시작하고, 연결 실패 시 코드 화면에서 재확인할 수 있습니다.

## 원인과 수정

1.1.4는 중앙 입력을 숨기고 오른쪽 채팅의 생성 승인으로 연결했습니다. 그 결과 화면에 코드 생성 기능이 열려 있어도 채팅의 승인 버튼을 누르기 전에는 설계 요청이 시작되지 않았습니다.

1.1.5는 중앙 입력에서 `code.plan`을 직접 전송합니다. 설계 응답은 기존 결정 모달에 표시하며, 별도의 채팅 승인 카드를 거치지 않습니다. 사용자의 설계 확인 전에는 코드 생성을 시작하지 않고, 파일 적용 전에는 생성 결과를 프로젝트에 쓰지 않습니다.

설계·생성 엔진은 탭 이동 시에도 유지합니다. 요청 시점의 폴더와 참고 파일, ADR, diff, 삭제 경고, 파일별 적용 확인을 보존합니다. 중복 전송과 한글 조합 중 단축키 오작동을 막고, 취소·오류·시간 초과 후 입력을 다시 허용합니다.

## 검증

- 확장 테스트 **390개 통과, 2개 건너뜀**. 호스트·웹뷰 TypeScript 검사와 프로덕션 웹뷰 빌드 통과.
- 신규 행동 테스트: 바로 설계 요청, 확인 전 생성·적용 금지, 폴더·참고 파일 유지, 중복 전송 방지, 빈 설계 확인, 취소·오류·시간 초과 복구, 늦은 응답 무시, 한글 조합 보호.
- 실제 배포용 웹뷰 + 컴파일된 확장 호스트 + 격리된 HTTP Core: 중앙 입력 → 설계 선택 → SQLite 선택 → 코드·ADR 생성 → 모두 적용 확인.
- 임시 프로젝트의 실제 `app.js`와 `docs/adr/ADR-001-storage.md` 저장 내용을 확인. 요청 로그에 `code.plan` → `code.generate` → `code.applyAll`이 기록되며 `chat.send`와 채팅 승인을 거치지 않음.
- Deploy 이동 후 복귀해 대화·적용 결과 유지 확인. 이어서 수정 요청과 설계 취소 후 입력 복구 확인. 우측 패널이 없는 화면과 설계 모달을 브라우저에서 시각 확인.
- 기존 HTTP 통합 하네스 통과: 이전 버전의 승인 요청 재시작 인계·중복 방지, 설계·코드·ADR·파일 적용.
- 최종 VSIX의 네이티브 Core 1.1.5 검증 통과: Python 없는 PATH·격리된 사용자 폴더에서 기동, 세션 인증, AI 미설정 진단과 Core 상태, 소스 분석, 미연결 AWS·미인증 GitHub 처리, 배포 계획·취소, 재시작·종료.
- VSIX 내부 manifest·호스트·웹뷰·아이콘을 현재 빌드와 바이트 비교. 설치 번들에 오른쪽 패널 식별자가 없고 중앙 대화 화면이 포함됨을 확인.
- VS Code CLI 설치 성공 및 `recoder-team.recoder@1.1.5` 확인. 실행 중인 VS Code 창은 강제로 새로고침하지 않았으며, 사용자가 **Developer: Reload Window**를 실행하면 반영됩니다.
- 설치 파일: `extension/dist/recoder-1.1.5-win32-x64.vsix` (64,140,674 bytes).
- SHA-256: `b0a42ca6e438de5b4f3145a87d134fd3345231ebaf970022e76116ecbbdfdffe`.
