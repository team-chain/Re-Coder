# ReCoder 1.1.6 — 실제 모델 코드 생성 실패 복구

## 문제와 수정

사용자에게 `LLM 응답에 적용할 ops 가 없습니다` 오류가 표시되었습니다. 기존 고정 응답 하네스는 라우터 아래의 모델 호출을 대체하므로 이 결함을 잡지 못했습니다.

- 코드 생성이 요청한 8,192토큰과 temperature를 통합 라우터가 전달하지 않았으며, Bedrock 비동기 호출도 inferenceConfig를 구성하지 않았습니다. 이제 구조화 응답·일반 응답·도구 대체 경로까지 값을 전달합니다. Gateway와 Gemini 클라이언트도 요청값을 보존합니다. Gateway 서버가 설정한 예산·출력 상한은 그대로 적용됩니다.
- 파싱 실패 시 `{raw_response: ...}`로 감싼 값을 정상 JSON처럼 다시 직렬화해 원인이 사라졌습니다. 원문을 정상 코드 결과로 오인하지 않도록 처리합니다.
- 코드 생성은 파일 작업 JSON 스키마를 요청하고, 빈 목록·깨진 JSON·누락된 파일 내용·잘못된 경로·중복 경로를 검사합니다. 일부 파일만 골라 성공 처리하지 않고 묶음 전체를 검증합니다.
- Bedrock의 `stopReason=max_tokens`는 명시적인 출력 잘림으로 처리합니다. 같은 요청과 승인된 설계로 교정은 한 번만 시도하며, 교정 실패는 원인과 파일 미변경 상태를 알려줍니다. 잘림을 공급자 장애로 간주해 모델을 바꾸지 않습니다.
- 생성과 한 번의 교정을 위해 확장의 생성 대기를 180초, 웹뷰 대기를 195초로 조정했습니다. 설계 확인·파일 적용 승인은 유지됩니다.

## 실제 Bedrock 검증

사용자의 기존 프로젝트를 변경하지 않고 격리된 테스트 프로젝트를 사용했습니다. 실제 공급자는 `bedrock`, 모델은 `global.anthropic.claude-haiku-4-5-20251001-v1:0`으로 확인했습니다.

1. Vite·React·TypeScript·Tailwind 게시판 요청으로 실제 설계 3개를 받았습니다.
2. 첫 생성은 실제로 **8,192 출력 토큰에서 잘렸습니다**. 수정된 경로가 이를 감지했습니다.
3. 교정 응답은 **7,674 출력 토큰, stopReason=tool_use**로 완결됐고, 코드·설정 파일 17개와 ADR 3개를 반환했습니다. 설계부터 교정 완료까지 69.03초였습니다.
4. 생성물의 최초 빌드에서 사용하지 않는 React import로 TS6133 오류 1개가 발견됐습니다. 이를 숨기지 않고 같은 실제 AI 수정 경로로 `src/App.tsx`만 수정했습니다. 이후 `tsc && vite build`가 통과했습니다. 생성 지시에도 JSX 설정과 import 일관성을 보완했습니다.
5. 생성된 앱을 브라우저에서 실행해 작성·상세보기·수정·검색 일치/불일치·새로고침 후 저장 유지를 확인했습니다. 브라우저 오류는 없었습니다.

이는 해당 테스트 요청에 대한 검증이며 모든 AI 생성 코드가 자동으로 빌드 검증된다는 의미는 아닙니다. 제품은 모델 응답의 파일 작업 형식을 검증하고 적용 전에 사용자의 검토를 받습니다.

## 자동 검증

- Core 관련 테스트 **209개 통과, 플랫폼 조건 1개 건너뜀**. 새 응답 검증과 실제 라우터·Bedrock 클래스에서 SDK 경계까지의 요청 전달을 테스트합니다. 기존 설계·ADR·삭제 경고·프로젝트 탐색·진단 테스트도 포함합니다.
- 확장 테스트 **390개 통과, 환경 조건 2개 건너뜀**. 중앙 대화, 설계 선택, diff·적용, 기존 배포 도구를 포함합니다.
- 생성은 프로젝트 파일을 자동으로 쓰지 않는다는 점을 실제 모델 검증과 자동 테스트에서 확인했습니다. 빌드·브라우저 검증용 저장은 격리된 테스트 프로젝트에서만 수행했습니다.

## 설치 파일 검증

- 완성된 VSIX를 풀어 Python이 없는 실행 경로와 별도 사용자 프로필에서 Core 실행·세션 인증·재시작·종료를 확인했습니다. 소스 구조 분석, AWS 미연결 상태, GitHub 미인증 처리, 배포 계획·포트·환경변수·취소 검증도 통과했습니다. 실제 클라우드 배포나 GitHub push는 수행하지 않았습니다.
- VSIX에 포함된 `recoder-core.exe`의 `/api/code/generate`를 기존 AWS 인증으로 호출했습니다. 실제 Bedrock이 5.92초에 완전한 `index.html` 변경을 반환했으며, 적용 전 프로젝트 파일이 생성되지 않았습니다.
- 확장 진입점·웹뷰·API 클라이언트·아이콘·Core 등 7개 파일이 빌드 결과와 일치했습니다. 패키지는 64,146,884바이트이며 SHA256은 `a77831edf56d4465c8036bc282f2734866aac73d183c654e8c5c17fff45eb966`입니다.
- 격리 검증 프로세스 종료와 VS Code의 `recoder-team.recoder@1.1.6` 설치를 확인했습니다.

## 업데이트

설치 파일은 `extension/dist/recoder-1.1.6-win32-x64.vsix`이며 현재 VS Code에 업데이트했습니다. **Ctrl+Shift+P → Developer: Reload Window**를 실행하고 ReCoder → Develop → 코드 생성·수정에서 다시 요청합니다. 열려 있는 사용자 창은 자동으로 재시작하지 않았습니다.
