# ReCoder 1.1.8 — 정적 배포 및 연결 흐름 복구

2026-09-25 03:36 영상과 실제 `test temp` 프로젝트를 기준으로 수정했습니다. 이번 프로젝트는 이전 Vite 프로젝트와 달리 `index.html`, `app.js`, `styles.css`로 구성된 순수 정적 사이트였습니다.

## 원인과 변경

- **Docker**: 정적 HTML 감지는 있었지만 Dockerfile 템플릿이 없어 unknown/Python 안내로 실패했습니다. AI·npm 없이 동작하는 nginx 템플릿을 추가하고, 일반 생성기·AI 생성기·API 폴백·Compose·ECS 헬스 판정에 연결했습니다. 자산 목록은 빌드 때 수집하므로 나중에 추가한 JS/CSS도 재배포됩니다. 최종 이미지는 비특권 사용자로 실행하며 숨김 파일·설계 기록·시크릿 파일을 제공하지 않습니다.
- **GitHub**: 연결만 지원하고 첫 커밋은 VS Code 소스 제어로 떠넘겼습니다. 캔버스에서 파일 선택, 작성자 확인, 커밋, 푸시 승인까지 이어집니다. 다른 스테이징 파일은 보존합니다. 확인 이후 파일이 바뀌면 커밋을 중단합니다. 자격증명·로컬 설정·의존성 파일은 선택에서 제외합니다.
- **ADR**: 생성된 문서의 `상태: 승인됨`을 무시하고 존재하지 않는 검토자 필드만 확인했습니다. 실제 승인 상태를 읽어 `설계 확정`으로 표시하며, 초안과 폐기 문서를 승인으로 간주하지 않습니다.
- **Discord**: 기본 알림 연결에 별도 봇 서버가 필요했습니다. 프로젝트별 웹후크 연결과 테스트 전송을 추가했습니다. URL은 VS Code SecretStorage에 저장하며 화면·오류에 반환하지 않습니다. Discord 공식 호스트만 허용하고 리다이렉트를 차단합니다. 연결 자체는 메시지를 보내지 않으며, 테스트 전송 버튼 또는 사용자가 켠 새 이벤트 알림만 전송합니다. 기존 봇 서버 연결은 고급 옵션으로 유지합니다.
- **S3**: 선택한 배포 대상을 사전 검사에 전달합니다. 정적 업로드에 컨테이너 이미지 검사를 요구하지 않으며, 환경 파일도 없는 HTML 사이트에 Git 설정을 강제하지 않습니다. 실제 환경 파일과 소스 시크릿 검사는 유지합니다. `.recoder`와 `docs/adr`는 정적 업로드에서 제외합니다.

Discord 구현은 [공식 Webhook API](https://docs.discord.com/developers/resources/webhook)의 토큰 조회·전송 계약을 사용합니다. 웹후크 관리 권한으로 채널 설정에서 URL을 복사해야 하며, 별도 봇 서버는 필요하지 않습니다.

## 검증 범위

- 배포·ECS·S3·GitHub·AI 오류 복구 Core 테스트: **565개 통과**.
- Dockerfile·Compose·스택 감지·ADR 추가 회귀 테스트: **210개 통과**.
- 확장 테스트: **396개 통과, 기존 2개 건너뜀**.
- 실제 사용자 HTML 프로젝트 복사본으로 Dockerfile 제안·승인 저장, hadolint, gitleaks, 이미지 검사, Docker build/run, HTTP 헬스를 실행했습니다. `recoder-qa-118` / `18118 → 3000`에서 `/`, `/health`, `/app.js`, `/styles.css`가 정상 응답했습니다. 내부 문서·시크릿·없는 파일 경로는 404였습니다. hadolint/gitleaks 발견 항목은 0개입니다.
- 실제 브라우저에서 배포한 게시판의 글 작성 및 새로고침 후 보존을 확인했습니다. 데이터 저장 방식은 사용자 소스의 브라우저 localStorage이며 서버 DB 검증을 뜻하지 않습니다.
- 격리 Git 저장소에서 첫 커밋·선택 파일·삭제·기존 스테이징 보존·검토 이후 변경 차단·로컬 bare 원격 푸시를 확인했습니다.
- 실제 React 화면과 SidebarProvider를 연결해 GitHub 연결 → 파일 선택 → 첫 커밋 → 푸시 승인/결과, Discord 연결/테스트 응답, ADR 설계 확정 표시를 클릭 검증했습니다. 이 화면 검증의 외부 API 응답은 픽스처입니다.
- **VSIX에서 추출한 Core 실행 파일**로 실제 Bedrock의 게시판 설계 및 코드 작업 반환, 정적 Dockerfile 생성, nginx Compose 헬스 검사, S3 사전 검사를 확인했습니다.
- Python이 없는 격리 실행 환경에서 Core 자동 시작, 세션 인증, AWS 미연결 표시, 프로젝트/파일 분석, 미인증 GitHub 요청, 배포 계획/취소, 재시작/종료를 확인했습니다.

실제 GitHub 원격 게시, 실제 Discord 채널 수신, 실제 AWS 리소스 배포는 이번 검증에 포함하지 않았습니다. 사용자 계정·채널·권한에 따른 외부 동작을 검증 완료로 주장하지 않습니다.
