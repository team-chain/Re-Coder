# ReCoder 1.1.2 검증 기록

검증일: 2026-09-24. Windows x64, `codex/improvements` 작업 폴더 기준.

## 자동 회귀 검사

| 범위 | 결과 |
|---|---|
| Core 전체 | 1,896 통과, 3 건너뜀 |
| 최종 스캔 보고서 보완 관련 재검증 | 42 통과 |
| VS Code 확장·웹뷰 | 369 통과, 2 건너뜀 |
| Discord 봇·로컬 HTTP 연동 | 79 통과 |
| TypeScript·프로덕션 웹뷰 빌드 | 통과 |

Core 전체 실행 후 Trivy `Results` 필드가 빈 객체·숫자·불리언인 경우도 검사 실패로 처리하도록 조건을 보완했고, 스캔 무결성·실패 사유·빌드 후 게이트 테스트 42개를 재실행했습니다. 건너뛴 테스트는 통과 수에 포함하지 않습니다.

## 실제 Docker 검증

제품의 배포 계획·실행·롤백 함수를 실제 Docker에 연결했습니다. 전용 컨테이너, 임시 작업 폴더와 별도 배포 이력 저장소를 사용했습니다.

1. 계획 생성 → 이미지 빌드 → 컨테이너 실행 → HTTP 헬스 및 환경변수 확인.
2. 의도적인 빌드 실패 뒤 기존 이미지와 HTTP 응답 유지.
3. 실행 파일이 없는 ENTRYPOINT로 시작 실패 → 기존 서비스 자동 복구.
4. 시작 후 앱이 종료되는 상황 → `health_ok=false`, 롤백 후보 부적격 표시 → 명시적 롤백 후 복구.
5. 같은 태그를 다시 빌드 → 새 이미지 ID와 새 HTTP 내용 확인.
6. 승인한 롤백 → 원래 이미지 ID·포트·환경변수·HTTP 내용 복원.
7. 실제 nginx 컨테이너 안에서 ECS용 wget 헬스 명령 실행 성공.

실행 시나리오는 보안 검사를 생략한 전용 테스트 요청으로 상태 전환을 확인했습니다. 보안 게이트 차단·오류·재시도는 회귀 테스트로 별도 검증했고, 테스트 React 이미지 ID에 실제 Trivy 검사도 실행하여 **CRITICAL 0건, HIGH 0건**을 확인했습니다. 이 결과는 검사한 런타임 이미지와 당시 DB에 한정됩니다.

전용 테스트 컨테이너는 종료·제거했습니다.

## 설치 파일 검증

Windows용 VSIX에 동봉한 Core를 별도 Python·개발자 AWS 자격증명이 없는 격리 사용자 환경에서 실행했습니다. 세션 인증, AWS 미연결 표시, 파일·함수 분석, GitHub 미인증 응답, 배포 계획의 최종 스테이지 포트·헬스 경로·환경변수, 실행 전 취소, Core 재시작 및 종료를 검사합니다.

배포 파일은 `extension/dist/recoder-1.1.2-win32-x64.vsix`이며, 같은 위치의 `.release.json` 및 `.vsix.sha256`에 동봉 Core와 VSIX의 해시를 기록합니다.

## 로컬 환경 복구

Docker Desktop 시작 로그에서 `dockerInference` 및 `engine.sock`의 Windows 오류 1920을 확인했습니다. 소켓 전용 폴더에 0바이트 임시 파일만 있는지 확인하고, Docker 프로세스 종료 후 폴더를 백업 이름으로 이동해 빈 런타임 폴더를 만들었습니다. 이후 Docker 준비와 위 실제 배포 검증이 통과했습니다. 이미지·볼륨·설정은 유지했습니다.

최종 소켓 백업은 `%LOCALAPPDATA%/Docker/run.recoder-stale-20260924-final` 및 `%LOCALAPPDATA%/docker-secrets-engine.recoder-stale-20260924-final`입니다. 단계별 복구 과정의 소켓 백업도 남겨 두었습니다. 같은 오류 양상은 [Docker 프로젝트의 Windows 시작 오류 보고](https://github.com/docker/desktop-feedback/issues/531)에도 보고되어 있습니다.

## 직접 확인이 필요한 외부 연동

실제 사용자 AWS의 ECS/S3 리소스 생성·업데이트, GitHub 원격 푸시, Discord 채널 메시지 전송은 수행하지 않았습니다. 관련 코드와 로컬 연동 계약은 테스트했으며, 각 사용자 계정의 권한·네트워크·정책까지 이 결과로 보증하지 않습니다.
