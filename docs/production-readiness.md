# 생성·배포·보안 검증 범위

빈 프로젝트에서 `실제 운영 가능한 쇼핑몰을 만들어줘`라고 요청하면 시작 방식을 선택합니다. **검증된 쇼핑몰 기반**은 React·Express·PostgreSQL·Stripe SDK 구성을 적용하고 `provider=starter`, `foundation=commerce-v1`로 기록합니다. AI 자유 생성과 구분하며, 기존 파일이 있는 프로젝트에는 덮어쓰지 않습니다. 선택은 ADR에도 남습니다.

생성 결과는 임시 사본에서 실제 Docker 빌드를 수행합니다. 원본 파일과 비밀값은 분리하고, 실패 로그를 이용해 자유 생성 코드를 교정합니다. Docker 미설치·중지·시간 초과는 통과로 표시하지 않습니다. 화면의 빌드 결과는 주문·결제 등 업무 정확성 검증과 별개입니다. 자유 생성은 모델 응답 잘림·시간 초과·의존성 및 코드 오류로 여전히 실패할 수 있습니다.

쇼핑몰 기반은 가입·로그인·검색·장바구니·주문·관리자 상품·재고 화면과 서버 가격 계산, 재고 예약, 주문 멱등성, 서명 웹훅, 관리자 권한 회수, 미결제 주문 정리를 포함합니다. 비밀값·실제 결제사 키·상품·통화·사업 정책은 운영자가 설정해야 합니다. 실물 배송·세금·환불·정산·알림·비밀번호 재설정은 이 기반의 구현 범위에 포함되지 않습니다. 실제 카드 결제는 계정이 없어 모의 결제로 검증했습니다.

부하 검사는 단일 256 CPU unit/512MiB Fargate 태스크의 제한된 읽기 시나리오입니다. 장시간 트래픽, 결제사 성능, 최대 처리량의 보장이 아닙니다. 복원 DB 준비는 425초였으며 네트워크 오류 진단·수정·빌드·재배포를 포함한 전체 관찰 시간은 약 24분입니다. 실제 서비스 중단 시간이나 보장 RTO가 아닙니다. 인증 API 캐시는 껐고, 인터넷에서 앱과 DB로 직접 들어오는 인바운드는 허용하지 않았습니다. RDS 통신은 인증서를 검증하는 TLS를 사용했습니다.

이번 결과는 검증된 기반을 선택한 경로입니다. AI 자유 생성의 과거 실패 사례를 성공으로 바꾸어 계산하지 않습니다. 36개 배포 오류 A/B/C/D 실험은 별도 자료이며 이 쇼핑몰 통과 결과로 비용 절감 비율을 새로 산출하지 않습니다.

실환경에서 발견한 ALB/ECS 가용 영역 불일치는 빌드 전 검사로 차단합니다. ALB 연결 시 앱 보안 그룹을 명시하도록 요구해 직접 접속용 공개 그룹이 자동 생성되는 경로를 막았습니다. 로그인 실패 제한은 계정별 DB 잠금으로 동시 요청에도 적용하고, bcrypt의 72바이트 제한을 가입·로그인 모두에 적용합니다. 데스크톱 상품 4열·모바일 2열 배치와 로그인·상품·장바구니·주문·관리자 스타일을 완성했습니다.
