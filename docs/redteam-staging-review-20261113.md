# staging 레드팀 출시 검토 — 2026-11-13

기준: `origin/staging`의 `c35196e4`에 레드팀 근거 검증 변경 `4b4fed91`을 반영하고, 팀의 추가 staging 변경 `4ae9ac54`까지 `57d0a3c3`으로 병합한 별도 작업 폴더. 기존 프로젝트 루트는 변경하지 않았다. 이번 레드팀 작업에서 Claude의 Core·다중 서비스 하네스 코드나 기존 AWS 연결·개발용 AI 설정을 수정하지 않았다.

## 이번 변경

- 별도 PentAGI 서버의 연결 정보를 프로젝트별 SecretStorage에 보관한다. 기존 연결은 마이그레이션하며, 진행 중인 원래 서버의 만료된 토큰을 다시 설정할 수 있다.
- 로컬 워커는 내부 전용 Docker 네트워크에서 실행한다. 고정 대상 HTTP 중계기만 접근할 수 있고, 다른 포트·경로 및 DELETE/PUT/PATCH/CONNECT를 거절한다. GET/HEAD/OPTIONS/POST, 최대 300개 요청, 약 5요청/초, 요청 64KiB·응답 256KiB 제한을 적용한다. 앱 자체가 다른 서비스에 요청하는 동작까지 이 계층이 통제하지는 않는다.
- 검사 도구는 공식 이미지 digest를 고정한다. 전용 엔진에서 직접 이미지를 받아 사용 태그의 내용 ID를 원본과 대조한다. Windows 바이너리 스트리밍의 시간 초과와 임시 레지스트리의 loopback 연결 실패를 실제 확인하여 두 경로를 제거했다. 새 검사마다 전용 엔진의 도구 이미지를 다시 받으므로 준비 시간과 인터넷 전송량이 크다. 호스트 Docker 소켓이나 프로젝트 소스를 워커에 마운트하지 않는다. 전용 DinD 엔진은 Linux VM 내부에서 privileged로 실행하므로 VM 수준의 추가 격리를 대신한다고 주장하지 않는다.
- Docker 데이터가 실제로 저장되는 드라이브를 확인한다. Windows junction을 실제 경로로 해석하며, Docker 드라이브 50GiB·검사 기록 드라이브 256MiB 미만에서는 이미지 다운로드 전에 중단한다.
- 사용자가 선택적으로 등록한 테스트 사용자 A·B의 소유 리소스를 정상·비로그인·교차 접근 6개 GET 요청으로 대조한다. 정상 소유자 응답이 확인되지 않거나 로그인 만료·리다이렉트·크기 제한이 발생하면 미검증으로 남긴다. 비밀번호·인증 헤더는 AI나 웹뷰에 전달하지 않는다. 관리자 권한과 등록하지 않은 경로는 이 결과에 포함되지 않는다.
- HTTP 요청 이벤트로만 움직이는 어두운 진단 화면을 제공한다. 대상, 요청 경로, 응답 상태, 소요 시간과 실제 PentAGI 작업을 표시한다. 연결이 끊기면 애니메이션도 멈춘다. 중단 버튼은 진행 화면 옆에 둔다.
- 직접 관찰한 HTTP 응답과 AI가 작성한 취약점 후보를 구분한다. CVSS는 벡터에서 계산하며, 빠진 검사·부족한 대조 근거·상세 보고서 수집 실패는 완료나 안전으로 바꾸지 않는다.

## 검증 기록

- 확장 타입 검사 통과. 확장 전체 테스트: **885개 중 882개 통과, 3개 건너뜀, 실패 0**. 저장 공간 안내, 최종 이미지 준비 경로, 진행 화면 버튼의 변경을 포함한다.
- 실제 루프백 HTTP: 정상/취약한 사용자 소유권 사례, 만료 인증, 리다이렉트, 과대 응답, 중단, 경로 우회, 제한 메서드, 비밀값 없는 이벤트 기록 검증.
- 실제 프로덕션 웹뷰 + 명시적인 테스트 응답: 진행, 연결 복구, 중복 시작 방지, 불완전 보고서, 1200/700/390px, reduced motion, 중단·정리. 이 결과는 실제 AI 정확도 검증이 아니다.
- Core 보안·관리형 빌드 연결 회귀 **95개 통과**. 실제 클라우드 호출을 하지 않는 mock 테스트다. 사용자 홈은 변경하지 않고 Python audit hook으로 외부 DNS·소켓을 거절한 환경에서 실행했다.
- 전체 Core 원본 결과: **3,542 통과, 14 실패, 25 건너뜀, Docker 빌드 1개 제외**. 전체 통과로 표시하지 않는다. CloudFront 관련 13개 실패의 공통 원인은 테스트의 Moto 5.2.2 `list_distributions()` 응답에 Comment·Origins 등 설정이 빠지는 현상으로 좁혔다. 실제 AWS를 호출하지 않은 최소 재현에서도 동일했으며, 배포용 SDK 버전으로 바꿔 읽어도 동일했다. 실제 AWS 정상 여부까지 증명한 것은 아니다.
- 나머지 Core 실패는 Windows 계약 테스트가 Node 자식 프로세스의 환경을 새로 만들면서 `SystemRoot`를 누락한 경우다. 별도 최소 재현에서 누락 시 exit 134/CSPRNG 오류, 유지 시 exit 0을 확인했다. 팀의 staging 병합 후 배포·하네스 회귀는 **29 통과, 2 실패**였고, 추가 실패는 Compose가 먼저 보고하는 비밀값 이름을 하나로 고정한 검사였다(실제 Compose는 다른 필수 비밀값 누락으로 정상 차단). 해당 팀 코드를 이번 레드팀 작업에서 수정하지 않았다.
- 최신 staging을 포함한 네이티브 Core 자체 검사, VSIX 배포 파일 126개 및 빌드 대조 79개 검사를 통과했다. Windows x64 후보는 `extension/dist/recoder-3.0.9-win32-x64.vsix`, SHA-256 `2b50000035f0a6c764ea8b6cf8979e783529292192bab0c4abf604f8bb440ff1`이다. Python 3.12.9로 빌드했다. 버전 3.1.0 정식 출시를 확정한 파일은 아니다.
- 실제 VS Code 1.145.2의 별도 프로필에 위 VSIX를 설치했다. 활성화, 기존 설정 보존, 번들 Core 기동과 인증된 상태 조회, Workbench·Develop·Security·Deploy 열기, Core 종료를 모두 통과했다. 사용자 프로필의 기존 설치와 계정 설정은 바꾸지 않았다. 증거: `.test-artifacts/vscode-3.0.7/verification-3.0.9.json`(폴더 이름은 기존 하네스 이름).
- 실제 Docker 준비·대상 격리·임시 API 인증·정리: **통과**. 허용 앱 200, 범위 밖 경로 403, DELETE 405, 인코딩 경로 우회 403, 엔진 API와 다른 대상 포트 차단, 비밀 쿼리 없는 HTTP 이벤트 4개를 실제 컨테이너에서 확인했다. 종료 후 세션 소유 컨테이너·볼륨·네트워크가 모두 없는 것도 별도 확인했다. 준비부터 정리까지 이 PC에서 약 **14분 50초**가 걸렸다(재현 기록이며 일반적인 성능 보장이 아님). [기계 판독용 실행 기록](verification/redteam-local-20261113.json). 이 하네스는 AI Flow를 생성하지 않고 실제 API 키를 쓰지 않는다.

## 아직 출시 근거가 없는 범위

1. 새 프롬프트와 실행 경로에서 유료 모델을 사용한 PentAGI 탐지 정확도 재검증. 이번 세션에는 비용 승인이 없다. 과거 로컬 GPT 실행의 SQL 취약점 누락이 해결됐다고 단정할 수 없다.
2. 모든 모델·프로젝트·프레임워크 조합, 운영 데이터가 있는 서비스, 대규모 부하와 장시간 장애 복구.
3. 별도 PentAGI 서버 운영자의 실제 네트워크 격리와 비용 상한. 클라이언트 주소 검증과 안내만으로 서버 egress를 보장하지 않는다.
4. 관리형 AWS 실행 실검증. 기존 계정 권한과 연결 방식을 변경하지 않으며, 이번 작업에서 AWS 리소스를 만들지 않았다.
5. 전체 Core 원본 검사의 실패 14건 및 팀 하네스의 플랫폼·검사 순서 문제 해소. 레드팀과 관계없는 코드의 실패를 이번 변경에서 무시하거나 전체 통과로 바꾸지 않았다.
6. 로컬 준비 시간·저장 공간 개선. 공식 검사 도구 이미지가 약 17GB로 크고 세션마다 전용 엔진에서 준비한다. 현재 50GiB 여유 공간을 요구한다. 설치 즉시 또는 몇 초 내 진단 시작을 보장할 수 없다.

## 재현

```powershell
cd extension
npm run lint
npm test
npm run build:webview
node harness/redteam-runtime-smoke.js
```

마지막 명령은 로컬 Docker 전용이며 50GiB 이상 여유 공간과 Docker Linux 엔진(메모리 6GB, CPU 2개)이 필요하다. 고정 이미지를 내려받고 전용 환경을 만들었다가 정리한다. 테스트 앱은 명령이 직접 루프백에 생성한다. 실제 API 키를 전달하지 않으며 모델 호출은 하지 않는다.

실행 결과와 상세 로그는 작업 폴더의 `.test-artifacts/`에 보관한다. 테스트 예시 화면을 실제 취약점 진단 결과로 사용하지 않는다.
